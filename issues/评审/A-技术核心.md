# A-技术核心评审：V2.3 §2（论文一致性核对）/ §3（变量选取机制）

## 结论（先行）

1. **§2.1 的"所有技术点与论文核心逻辑保持一致，无表述偏差"不成立（P0-5）**：既有对论文口径的取舍未声明（Alg1 的 f_e vs s），也有对现有代码的误述（阈值 0.70/0.90 被写成 0.5/0.6；宣称的 s_e 指标在代码中不存在；GAM-ANM 被当作 DiffAN 的等价替换）。
2. **§3 漏斗骨架可用，但阶段 2 评分的三个核心量里至少一个方向是错的、一个统计单位无法自洽（P0-1、P0-2）**：`cross_traj_variance` 的代码含义与文字定义相反；`MI(v, severity)` 在"轨迹内严重度为常数"的前提下，要么恒为 0，要么度量的是"轨迹间均值偏移"（即效应幅度），系统性偏向效应变量/marker。
3. **§3.4 伪代码不是 §3.2/§3.3 的可执行落地（P0-4）**：缺失率、全程零值两条硬规则没有代码；`raw_data.columns` 含 trajectory_id 会直接报错；强制变量回填会互相覆写；`len<15` 无补足分支。
4. **§3 的可辨识性/样本量论证缺失（P1-2）**：按严重度分组后每组训练轨迹仅 ≈26–28 条，p=20–25 时有向边 380–600 条；Bootstrap 100 次下 f_e=0.5 的 95% 区间约 ±0.10（B=50 时 ±0.14），阈值 0.5 与抛硬币不可分辨。
5. **§3 与 §2.6 第 3 条 / §4.5 / §4.6 存在三处直接冲突（P0-2、P1-11）**，需先定"变量选取的统计单位与严重度处理边界"，再谈实现。

> 判定口径：P0 = 结论/公式错误或规范不可执行，必须改；P1 = 实质缺陷，影响有效性/可复现性；P2 = 建议。行号为附件 V2.3 原文行号（与 `方案/NPPAD-CausalTrace-v2.3方案-…md` diff 相同）。
