## 一、概述

阶段 1–4 我们学完了 CausalTrace **论文本来怎么做**：神经符号三环节（阶段 1）、四 Agent 系统架构（阶段 2）、三大算法"筛选 → 量化 → 验证"（阶段 3）、评估体系（阶段 4）。阶段 5 要学的是另一个问题：

> **同一套方法，换到一个条件差得多的真实（仿真）数据集上，每一处为什么必须改、改成什么、改完还能声称什么。**

这份复现方案要做的事，一句话概括：

**在 NPPAD 的 100 条 LOCA（热段失水事故）仿真轨迹上，检验静态 LiNGAM 能否稳定恢复一组预先冻结、有物理依据的变量关系（核心是 WLR 泄漏流量与一回路压力 P 的关系）。**

它不是对原论文的严格复现，而是**方法迁移与适配**。读懂它的钥匙只有三把，全部 80% 的篇幅都值得花在这三件事上：

1. 🎯 **数据集没有变量级答案** → 任务从"根因溯源"降级为"上游因果定位"，评估从准确率改为物理一致性对照（3.2、3.12）。
2. 🎯 **数据形态违反 i.i.d.** → 独立单位是 100 条轨迹而不是 12,100 个时间点。方案里近一半的设计（轨迹级抽样、轨迹级划分、f_e 重新解释、严重度分组、窗口选择）都是这一条的推论（3.4、3.5、3.8、3.11）。
3. 🔧 **没有核电知识库** → 神经符号层用"极简本体 + 数据驱动阈值 + 模板解释"轻量替代，且每一处替代都诚实标注效力降级（3.7）。

其余内容（Phase 编号、Day 排期、非线性引擎选型、扩展矩阵）都是这三条主线的工程展开，可以速读。

> **关于 2026-10-25 第二轮辩证修订**：方案在成稿后又经过一轮外审，提出"检验非高斯假设、重审标准化、提升严重度异质性地位"三点。最终立场是**接受问题诊断，但不照单接受解法**：非高斯性只加诊断、不加运行门槛（3.6）；标准化保留全局 Z-score、不切换轨迹内（3.4）；严重度分组从补充分析提升为关键稳健性检查，并冻结三类解释规则（3.8）。三处修订有一个共同精神——**让假设违背的程度可见、让解释边界清晰，但不假装能用工程技巧"修复"静态方法对动态数据的根本不适用**。

**与阶段 1–4 的阅读关系**：阶段 3 记住的口诀"Algorithm 1 = 筛选、Algorithm 2 = 量化、Algorithm 3 = 验证"在这里依然成立，但**三个算法在新数据上各自改了口径**——Alg1 从单指标变四指标、Alg2 强调逐次求逆、Alg3 直接被降级为探索性检查。读的时候不断问自己："论文的这个前提，在 NPPAD 上还成立吗？"

## 二、核心概念速览

| 概念 | 一句话定义 |
|------|-----------|
| NPPAD | 清华核研院用 PCTRAN 软件仿真的压水堆事故时序数据集，1217 个运行参数 CSV、18 类工况 |
| PCTRAN | 国际通用的核电站仿真软件，事故类型、破口大小、仿真时长都由人工配置注入 |
| LOCA | Loss of Coolant Accident，一回路失水事故；本方案只用其中的**热段**破口（LOCA，100 条） |
| 严重度 | LOCA 文件名 1~100，即破口面积占 100 cm² 的百分比；编号即标签 |
| 轨迹（trajectory） | 一次独立仿真从 t=0 到结束的完整时间序列；**本研究真正的独立样本单位** |
| 主窗口 | 主动选定的 t=300~1500s 区间，每条轨迹取 121 个等间隔点 |
| i.i.d. | 独立同分布；LiNGAM 的前提假设，连续事故时序不满足 |
| 自相关 / 伪重复 | 相邻时间点高度相关；把同一条轨迹的时间点当独立样本会虚增样本量 |
| 变量级 Ground Truth | "具体哪个变量是根因"的标签；NPPAD 没有，只有事故类型标签 |
| 故障响应变量 | 事故中异常表现的变量（如 WLR↑、P↓），是"症状"不是"根因标签" |
| WLR↔P 动态耦合 | 压力驱动喷放、泄漏又导致失压，物理上是双向反馈环，DAG 无法表达 |
| 竞争假设 | 不预设 WLR→P 为唯一正确方向，学出 P→WLR 也不算错，两个方向分开报告 |
| 遗漏混杂（omitted confounder） | 严重度是**已观测但未纳入建模**的共同原因，会同时驱动所有响应变量 |
| 轨迹级 Bootstrap | 重采样单位是整条轨迹（=重抽严重度构成），不是时间点 |
| f_e | 有向边在 N 次重采样中的出现频率；本方案读作"对严重度构成变化的敏感度"，**非置信度** |
| 常量列 | LOCA 下全程不变的参数（18~25 个），无分布、不可进 LiNGAM，审计时剔除 |
| 物理先验变量集 | 依据物理知识预先选定的 ~14–20 个变量，主实验不用 XGBoost 选变量 |
| 极简核电本体 | 用 JSON/字典实现的"变量 → 子系统 → 物理关系"三层结构，替代论文的 Neo4j 知识图谱 |
| 分段异常阈值 | 用唯一一条 Normal 轨迹分段算 μ±3σ 近似论文的专家公差；探索性，有整体退出条件 |
| 三分类报告 | 结果分实现正确性 / 统计稳定性 / 物理一致性三类陈述，不可互相替代 |
| 双引擎主线 | LiNGAM + GAM-ANM 并列运行（忠实于论文 LiNGAM/DiffAN 并列设计），结果经共识边 + RRF 融合为主 RCA 输出；GAM-ANM 替代完整 DiffAN |
| 非高斯性诊断 | 偏度/峰度/JB + 分布图的模型假设体检；**描述性证据，不是 LiNGAM 的运行开关**（堆叠时间点非独立，JB 的 p 值不按 N=12,100 解释） |
| 全局 vs 轨迹内标准化 | 主方案保留全局 Z-score（不制造/消除混杂）；轨迹内标准化会压掉严重度的物理水平差异、放大准稳态波动，仅作敏感性对照 |
| 双结果报告 | 混合主分析图与严重度分组稳健性结果预注册分开陈述；分组重在揭示异质性、界定解释边界，不保证比混合图更准 |
| 复用矩阵 | 扩展到新事故时：算法工程层直接复用，物理约束层（变量集/关系/本体/窗口）必须重建 |

## 三、知识分类详解

### 3.1 NPPAD 数据集：一份"没有变量级答案"的核电仿真试卷

#### 是什么

NPPAD（Nuclear Power Plant Accident Dataset）是清华核研院 2022 年发表于 *Scientific Data* 的公开数据集，用成熟的核电站仿真器 **PCTRAN** 生成：反应堆从 100% 功率稳态启动，人工配置事故类型与破口参数，仿真器自动演化，输出 96 个运行参数（加 TIME 共 97 列）、10 秒一步的时间序列。

#### 与论文原数据集的对比

| 维度 | NPPAD（核电，本方案） | FF Lab（论文原始） |
|------|---------------------|-------------------|
| 样本单位 | **100 条 LOCA 独立仿真轨迹** | 285 个真实装配周期 |
| 时间点规模 | 主窗口 100 × 121 = 12,100 行 | 166K 条记录 |
| 变量数 | 96 个参数（常量列剔除后 ~15–20 入模） | 筛选后 8 个 |
| 采样 | 10 s/步；原始轨迹 343~475 行（3420~4740s） | 1.95 Hz |
| 标签 | 事故类型 + 严重度（仿真注入值） | 缺哪种零件（变量级根因标签） |
| 初始状态 | 额定稳态：P=155.5 bar、TAVG=310°C、PWNT=100% | 21 个操作状态分段 |

> **一个已经踩平的坑**：官方 `Data Processing.py` 里 `iloc[:150]` 只是监督学习取前 150 行（0~1490s）的截断，**不是原始数据长度**。原始 LOCA CSV 实测有 343~475 行。方案早期版本误把 150 行当数据全长，2026-10-25 实测后更正——这提醒我们：**数据集自带的处理脚本服务于它自己的任务（事故分类），不服务于我们的任务（因果发现）**。

#### 本地 CSV 实测（我已用 `NPPAD_info/` 样本复核）

| 观测 | LOCA_1（1% 小破口） | LOCA_100（100% 大破口） |
|------|--------------------|------------------------|
| t=0 初态 | P=155.5 bar，TAVG=310°C，WLR=0 | 同左（所有轨迹同一起点） |
| WLR 首次非零 | **t=110s，WLR=32.18 t/h**（事故注入时刻） | t=110s，WLR≈3095 t/h（喷放峰值） |
| t=300s | P=154.1 bar，WLR≈33.7 | P=69.4 bar，WLR≈367 |
| t=1500s | **P=157.1 bar（已恢复并略超初值）**，WLR≈34.2 | **P=44.4 bar（持续失压）**，WLR≈228 |

Normal 轨迹（302 行，0~3010s）：PWNT 从 100% 持续降到约 40%、TAVG 从 310°C 降到约 299°C——**它是一条功率漂移轨迹，不是恒定稳态正常工况**（3.7 会再用到这个事实）。

#### 两个工程细节

1. **CSV 列顺序 ≠ README Table 2 的变量 ID**。例如压力 P 在 CSV 第 2 列，但在 Table 2 字典里 ID=79；WLR 在第 19 列，ID=18。代码必须 `df["P"]` 按列名访问，启动时做白名单校验，禁止用 ID 做 `iloc`。
   **408 类比**：Table 2 ID 像枚举常量的数值，CSV 列号像结构体在内存里的字段偏移——两套编号体系，拿枚举值当偏移量去取字段必错。
2. **18~25 个常量列**：剂量变量、严重事故晚期变量、未触发的系统动作在 LOCA 全程不变（小破口更多，25 个；大破口 18 个）。零方差变量没有分布、进不了 LiNGAM，审计阶段必须剔除并记录清单。

### 3.2 第一个根本变化：没有变量级 Ground Truth，任务从"溯源"降级为"上游定位"

#### 为什么这是根本性变化

阶段 4 学过，论文的 MAP@3=94%、MRR=0.92 之所以能算，是因为每条异常都有**变量级标准答案**："缺了鼻锥零件" → 根因变量是确定的，预测排名可以直接判对错。

NPPAD 不提供这种答案：

- 仿真时人工设定的"破口面积"是注入参数，**96 个运行参数中没有任何一列记录它**；
- 数据里能看到的 WLR↑、P↓、VOL↓ 全是事故发生后系统的**响应（症状）**，连 WLR 本身都只是"破口流量"这个故障过程的测量，不是注入开关。

所以"找出根因变量"在这份数据上无答案可对。方案把任务重新定义为：

> **给定异常目标变量 P（一回路压力），定位它的因果上游变量，检验学到的因果图能否恢复预先冻结的已知物理机制。**

#### 新任务的"标准答案"长什么样

不是一个标签，而是一张**实验前冻结的物理关系清单**（方案第三节），每条关系标注证据等级：

| 关系 | 含义 | 证据等级 |
|------|------|---------|
| WLR ↔ P | 泄漏流量与压力双向耦合（核心待检验） | 变量字典 + 物理模型 |
| WLR → VOL | 泄漏导致一回路装量下降 | 合理假设 |
| VOL → LVPZ | 装量影响稳压器水位 | 合理假设 |
| THA → PSGA | 热段温度影响二回路蒸发器压力（一回路→二回路传热） | 明确依据 |
| RH → PWNT | 总反应性驱动核功率 | 明确依据 |

**预注册纪律**：这张表必须在看任何实验结果之前冻结，"不事后改写以符合预期"。

**408 类比**：论文数据集像带标准答案的习题册（能算准确率）；NPPAD 像只有"评分要点"的开放题——不能打分对错，只能评"答案覆盖了几个要点、方向对不对"。而且评分要点必须考前公示，考后改要点就是作弊。

#### 由此连带的术语降级

方案通篇把"根因分析（RCA）"改称为**上游因果定位**。WHPI（高压注水）、WECS（安注总流量）这类事故后上升的变量明确标注为**系统响应、非根因**——不能因为它们和 P 同时变化就当成原因（安全系统是"救护车"，不是"肇事者"）。

### 3.3 最小核电物理：LOCA、14 个变量与 WLR↔P 反馈环

> 不需要成为核工程专家，只需掌握与选定变量有关的最小物理图景。

#### LOCA 的物理链条

一回路是携带堆芯热量的高压密闭水路（约 155.5 bar、310°C）。热段管道出现破口后：

```
破口出现（t≈110s 注入）
   │
   ▼
冷却剂喷放外泄：WLR↑（泄漏流量，破口越大初期越猛）
   │
   ├──► 一回路装量减少：VOL↓ → 稳压器水位 LVPZ 波动
   ├──► 一回路失压：P↓（大破口持续跌；小破口可被安注补偿后恢复）
   ├──► 温度/传热响应：TAVG、THA 变化 → 二回路 PSGA 波动
   └──► 安全系统动作（响应，不是原因）：WHPI 高压注水↑、WECS 安注总流量↑
```

#### 全方案的"戏眼"：WLR 与 P 的双向耦合

物理上这两个变量互为因果，构成一个**动态反馈环**：

- **P → WLR**：破口内外压差驱动喷放，压力越高，喷放流量越大；
- **WLR → P**：冷却剂漏走，一回路装量减少，压力被拉低。

而阶段 1 学过，因果发现算法（LiNGAM）输出的是 **DAG——有向无环图**，天生表达不了环。静态算法面对反馈环只会**随机挑选一个方向**输出。因此方案规定：

- 不预设 WLR→P 为唯一正确方向；
- LiNGAM 学出 P→WLR **不算错**；
- 把 WLR↔P 作为**竞争假设**，两个方向各自报告出现频率与稳定性，评估时**不把两个方向都算成正确**。

**408 类比**：DAG 像操作系统里无环的资源分配图（有环即死锁，被排除）；但 WLR↔P 是真实物理世界里的反馈电路，类似两个进程通过管道**双向**收发数据。你无法用一条单向箭头如实画出双向管道，只能报告"算法这次选择了数据流向的哪一臂"。

#### 本地数据对竞争假设的直接印证

- 大破口（100%）：t=110s 时 WLR 瞬间冲到 3095 t/h，P 在 200s 内从 155.5 跌到 77.5 bar——**压力驱动喷放**的信号极强；
- 小破口（1%）：WLR 很快稳定在约 34 t/h，P 在 t=300s 后靠补偿系统恢复到 157 bar——主窗口内 WLR↔P 的瞬态耦合**已经基本结束**，学不出这个方向不代表机制不存在。

同一条物理机制，在不同严重度轨迹上的可观测信号完全不同——这是 3.8、3.11 一切"严重度"讨论的物理来源。

### 3.4 第二个根本变化（全方案最重要）：独立样本单位是 100 条轨迹，不是 12,100 个时间点

#### 那个诱人的错觉

主窗口 100 条轨迹 × 每条 121 个点 = **12,100 行数据**。看起来是个很漂亮的样本量，LiNGAM、Bootstrap 似乎都有充足数据。错。

#### 为什么错：相邻时间点不独立

同一条轨迹上，t 时刻的 P 和 t+10s 的 P 几乎相同（强自相关），它们不是两次独立观测，而是**同一次事故演化的连续快照**。LiNGAM 的假设是：每行是从同一分布独立抽取的样本（i.i.d.），靠非高斯独立性辨识方向（阶段 1 的 ICA 直觉：嘈杂房间里分出声源）。喂给它 12,100 个高度相关的时间点，后果是：

1. **伪重复（pseudoreplication）**：有效信息量被夸大 100 倍。真实独立单位只有 100 条仿真轨迹；
2. **共同时间趋势被误判为因果**：事故发展期所有变量一起随时间变化，算法容易把"都随 t 变"读成"A 导致 B"。

**408 类比**：
- 把同一进程连续打出的 12,100 行日志当成 12,100 次独立实验——其实只运行了 100 次程序，每次产生 121 行；
- 或视频任务里把同一视频的相邻帧当独立样本划分——训练帧和测试帧几乎一模一样，准确率虚高。

#### 这一条推导出方案的四个核心设计

| 设计 | 内容 | 防的是什么 |
|------|------|-----------|
| **轨迹级 Bootstrap** | 重采样单位是整条轨迹（抽 80 条、拼接、学图），重复 100 次 | 时间点抽样导致的伪重复 |
| **轨迹级 80/20 划分** | 80 条训练、20 条验证，同一轨迹的点绝不跨集合 | 轨迹泄漏（测试集见过同一条事故） |
| **禁止跨轨迹构造特征** | 不跨轨迹算差分/滞后变量；每条轨迹独立清洗 | 人为制造不存在的关联 |
| **有效样本量按轨迹计** | 一切统计口径以 N≈100 为分母，Day 1 还要用 ACF 衰减估自相关时间 | 用 12,100 行自欺 |

> **Z-score 标准化不能救场——但也不该被换掉（2026-10-25 辩证修订）**：
> - 标准化只统一量纲（bar、t/h、°C 才能比较效应大小）。它是逐变量的固定线性变换（减常数、除常数），**不制造、也不消除严重度混杂**——严重度对 P 的影响在原始数据里就已存在；它同样不改变响应形态差异，同轨迹时间点照样相关。
> - 有人建议改用**轨迹内标准化**（每条轨迹减自己的均值、除自己的标准差），方案讨论后**不采纳为主方案**：这会压掉轨迹间的绝对水平差异，而"1% 组 P≈155 bar、100% 组 P≈50 bar"的水平差异**本身就是严重度的物理表现**；它还会放大 LOCA_1 这类准稳态轨迹（P 在 154~157 bar 内缓变）中的微小波动，制造虚假相对变化。
> - 最终口径：**全局 Z-score 维持主方案**，μ、σ 在训练集上一次性估计，验证集与每轮 Bootstrap 沿用同一口径（防止口径漂移式泄漏）；配套两项检查——按严重度组核对标准化前后分布（必做）、用轨迹内/组内标准化重跑做敏感性对照（扩展项，仅报告差异、**不据此挑"好看"的版本**）。

#### 静态近似的定位

明知 i.i.d. 不满足仍使用静态 LiNGAM，方案把它明确表述为**静态近似**：研究结论仅覆盖"事故发展期变量间的静态响应关系"，并把"静态方法在强自相关动态反馈系统上的适用边界"本身当作有价值的研究问题——**即使 WLR↔P 方向学不出来，这个"失败"也是关于方法边界的真实发现**。

### 3.5 时间窗口：为什么主动只看 t=300~1500s

#### 事故的四个阶段（本地轨迹图核对）

```
0 ────── 110 ────── 300 ────────────── 1500 ──────► 3420~4740s
│ 事故前  │  早期    │     发展期（主窗口）         │ 后期      │
│ 额定稳态│ 注入突变 │  WLR上升沿在此结束           │          │
│        │ WLR 0→非0│                              │          │
└────────┴──────────┴──────────────────────────────┘……
```

#### 选 300~1500s 的三条理由

1. **等长对齐**：100 条轨迹在该区间时间戳完整，恰为 300,310,…,1500 共 121 点，拼接后每条轨迹权重一致；
2. **避开最危险的区间**：t≈110s 的注入阶跃和 110~300s 的 WLR 快速上升沿是"共同阶跃/共同趋势"最强的阶段，静态 LiNGAM 最容易把时间趋势误判为因果边；
3. **研究对象明确**：只声称分析"事故发展期的静态响应关系"，不声称覆盖事故触发与早期传播。

#### 必须如实接受的两项代价

- 1% 小破口在主窗口内 P 已恢复（154→157 bar）、WLR 平稳，早期瞬态信号消失，**学不出 WLR↔P 属预期**；
- 丢失因果链随时间传播的信息。早期窗口 t=110~600s 只作为"时间允许时"的定性对照，两套结果不混用指标。

**408 类比**：分析程序的稳态性能时主动避开启动阶段——所有线程在启动时一起经历加载、初始化，那种"共同变化"是启动流程造成的，不代表模块间有因果依赖。但你也要声明"结论不适用于冷启动"。

#### 窗口冻结规则

窗口边界以 Phase 0 全轨迹曲线图确认为准；**审计后若调整窗口，必须记录理由并重做全部下游分析，禁止看到结果后再回头选窗口**。这是防止"哪个窗口出想要的结果就用哪个"的纪律性设计。

### 3.6 Phase 0：数据审计与"防泄漏"纪律

Phase 0 不是简单的数据清洗，而是一整套**在任何模型拟合之前完成**的校验与冻结。除了 3.1 的列名校验、常量列剔除、3.4 的轨迹原则外，最关键的是执行顺序：

#### 防泄漏的强制顺序

```
① 数据审计完成
      ▼
② 先划分：以轨迹为单位 80 训 / 20 验，划分结果固定记录
      ▼
③ 仅用训练集做一切"模型选择"：
     μ/σ 标准化参数、LiNGAM 学图、本体约束、
     Bootstrap、四指标、稳定边阈值
      ▼
④ 验证集只用一次：把冻结的图结构和标准化参数套上去，
     只做 Algorithm 3 的一致性比较
```

> **反例（明文禁止）**：先用全部 100 条轨迹跑完 Bootstrap、筛好边、定好阈值，再从中划 20 条当"验证集"——此时验证集已经参与了模型选择，一致性比较不再独立，等于用考试题划定考试范围。

**408 类比**：这正是机器学习入门的铁律——归一化参数只能从训练集估计、特征选择不能见测试集。方案额外加的一层是：泄漏单位不是"行"而是"整条轨迹"，因为同一事故的相邻时间点是一个整体。

#### 其他审计项

- 结构校验：TIME 严格递增、间隔严格 10s、无缺行重复行；文件名 1~100 与严重度一一对应；
- 初始状态检查：所有轨迹 t=0 同一起点（实测 155.5 bar / 310°C / 100%），避免模型把初始差异当事故关系；
- 严重度异质性审计（必做）：低(1–33)/中(34–66)/高(67–100)三组各抽 ≥3 条画全轨迹图，比较响应形态，输出审计小结作为 3.8 分组学图的输入；
- 不混用变功率数据：`Variable_Power_Data/` 注入时刻不同（约 905~2303s）且只有 mdb，本次不转换、不使用。

#### LiNGAM 假设诊断（非高斯性）：体检，不是门禁（2026-10-25 新增）

阶段 1 学过，LiNGAM 能辨识方向靠的是**一整组假设**：线性结构、无环图、误差相互独立且非高斯。此前方案直接默认它能跑，第二轮修订在 Day 1 增加了一项低成本诊断：

- 对每个入模变量记录**偏度、超额峰度**，画直方图 / QQ 图，可附 **Jarque–Bera 正态性检验**；
- 关键变量（P、WLR、VOL、TAVG 等）的分布按**严重度组 × 时间阶段（早期/发展期）**交叉观察，看分布形态是否随组、随阶段变化。

为什么强调它"**不是开关**"——这是辩证采纳意见的关键，两个方向都不能绝对化：

1. **观测变量非高斯 ≠ 方向必然可辨识**：可辨识性来自"误差非高斯 + 线性 + 无环 + 独立"整组假设同时成立；
2. **某个变量没通过正态性检验 ≠ LiNGAM 就可靠**；
3. **JB 的 p 值不能照字面解释**：堆叠后的 12,100 个时间点强自相关、不是独立样本，按 N=12,100 解释显著性会严重夸大；检验只作分布形态的描述性证据（可辅以按轨迹/按组计算的偏度峰度交叉核对）。

所以诊断结果**不改变主算法、不设"通过才运行"的硬门槛**，只决定结果解读该多保守、局限怎么写。即使非高斯性看起来很明显，时间依赖、WLR↔P 反馈环、机制异质性仍可能让方向输出失去依据——这部分风险继续由 f_e（2a）、分组一致性（2b）和物理对照共同刻画。

**408 类比**：这像上线前做代码静态扫描——扫描通过不代表系统一定没 bug（运行时问题、架构问题它看不见），扫描报红也不代表服务不能上线。它是让"假设被违背到什么程度"变得可见的体检，而不是决定程序能否启动的门禁开关。

### 3.7 神经符号层的轻量适配：论文三层知识 → 方案三件套

阶段 1、2 学过论文的三层知识注入：RDF 知识图谱 + Neo4j 过程本体（专家公差）+ 因果图提示注入。NPPAD 没有核电领域知识库，方案用轻量件实现**同等功能**，并在每一处标注效力差距。神经符号在本方案中不是可选项，而是四个 ★ 必选环节：Phase 0.5 构建 → 1.5 约束 → 3.5 异常标记 → 5.5 解释生成。

#### 三件套对应关系

| 论文组件 | 方案替代 | 效力声明 |
|---------|---------|---------|
| RDF 知识图谱（实体关系） | **极简三层本体**：变量 → 子系统 → 物理关系，用 JSON/字典 | 结构对等，规模远小 |
| Neo4j 过程本体 + 专家 cycle-aware 公差（21 个操作状态） | **分段数据驱动阈值**：用 1 条 Normal 轨迹分段算 μ±3σ | **仅探索性异常评分，不是经验证的运行容差** |
| LLaMA3-70B + 因果图提示注入 | **DeepSeek V4.1-Flash LLM**（有 key 时）/ 模板驱动（无 key 降级）+ 因果图提示注入 + 忠实性校验防幻觉 | 已实现 LLM 生成，防幻觉双保险（Prompt 约束 + 数值校验） |

极简本体的每个变量记录四元信息：中文含义+单位、所属子系统（一回路热工/流量/反应性功率/蒸发器/安全壳/安全系统）、角色（系统状态/过程/控制动作/安全指标）、物理关系（含方向、依据、证据等级）。

#### 本体约束的三类边（Phase 1.5，理解神经符号适配的关键）

| 类别 | 操作 | 例子 |
|------|------|------|
| **禁止边** | 从数据学到的图中**删除**，必须记录物理依据和删除前后差异 | 辐射 RM1→温度 TAVG、剂量 DTHY→P（物理上不可能） |
| **允许边** | 数据**已学到**才标记"本体支持"，权重不变；**数据没学到，绝不强行添加** | THA→PSGA |
| **未知边** | 完全不裁剪，数据决定 | WLR↔P（双向耦合不预设） |

"**允许边只标记、不添加**"是整个神经符号适配里最值得体会的一条原则：

- 如果因为物理上"应该有"THA→PSGA 就手动加边，最后图变漂亮了，却无法分辨这条边是 LiNGAM 学出来的还是规则塞进去的——知识污染了数据证据；
- 只标记不添加，保证**最终图里的每一条边都可追溯到数据来源**，本体只负责删（禁止边）和贴标签（允许边），不负责造边。
- 约束还必须施加在 Bootstrap 筛边**之前**，并通过消融对比"无约束图 vs 有约束图"来量化本体的增量价值。

**408 类比**：允许边只标记 ≈ 代码审查时在符合规范的行旁边批注"符合 §3.2"，但绝不动代码逻辑；禁止边 ≈ 明确非法的写法直接删除并留 commit 记录。手动加允许边等于审查者直接往你的代码里塞实现——之后谁也说不清行为是谁的意图。

#### 阈值模块为什么自带"退出条件"

论文的公差由专家基于 21 个操作状态定义，有工程效力；方案只有 1 条 Normal 轨迹，而 3.1 已实测它是**功率漂移轨迹**（PWNT 100%→40%、TAVG 310→299°C）。对功率变量分段算 μ±3σ，分段内的均值变化本身就是真实功率变化，不是"正常波动带"，3σ 的统计覆盖含义不成立。

因此方案规定：

1. 逐变量画图判定趋势来源（功率漂移 / 基线漂移 / 本应平稳），**去趋势不是默认操作**（可能减掉真实的功率-温度耦合）；
2. 只对分段内确实近似平稳的变量（如 P：155.5→157.1 bar）建阈值，功率相关变量默认不建；
3. **若可信变量过少，Phase 3.5 异常标记整体标记"数据不支持"并退出**——主排序（纯总效应）不依赖它，不得为跑通神经符号流程硬造阈值。

#### 【2026-10-25 关键修订】Normal 与 LOCA 功率演化不对应——阈值模块的根本问题

上述"退出条件"只解决了 Normal 轨迹内部的功率漂移问题，但**实测发现了一个更根本的问题：Normal 轨迹的功率演化路径与 LOCA 事故轨迹完全不对应**。

##### 实测数据对比（PWNT 核功率随时间变化）

| 时间 | Normal | LOCA_1 (1%) | LOCA_25 | LOCA_50 | LOCA_100 |
|------|--------|-------------|---------|---------|----------|
| 0s | 100% | 100% | 100% | 100% | 100% |
| 110s | **82.4%** | 100.4% | 101.2% | 101.3% | 101.6% |
| 300s | **49.5%** | 100.6% | 3.1% | 3.0% | 3.0% |
| 1500s | **40.2%** | 100.8% | 1.7% | 1.7% | 1.6% |

三种完全不同的功率演化模式：
- **Normal**：从 100% 缓慢降负荷到 40%（人为降功率过程，非事故）
- **LOCA_1（小破口）**：维持 100% 到 t≈2000s，然后安全停堆到 2%
- **LOCA_25+（中大破口）**：事故注入后迅速停堆到 ~2%

##### 问题的严重性

用 Normal（100%→40% 降负荷）分段算出的 μ±3σ 阈值，去和 LOCA（100% 维持或迅速停堆）比，**功率水平根本不匹配**：
- Normal 里 PWNT≈40% 的"正常带"，去判断 LOCA 里 PWNT≈100% 的点，全是"异常"
- Normal 里 TAVG≈299°C 的"正常带"，去判断 LOCA 里 TAVG≈310°C 的点，全是"异常"
- 这意味着阈值模块对功率相关变量完全失效，而热工变量里大部分都和功率耦合

##### 改进方案：用 LOCA_1 恢复段作为"100% 功率准 Normal"

**不需要外部标准数据**（公开的核电正常运行数据集要么不对齐变量/采样率/工况，要么不公开）。LOCA_1（1% 小破口）的恢复段本身就是最好的 100% 功率基准：

1. **LOCA_1 的 100% 功率稳态段为 t=520~2030s，共 152 个数据点**，稳态时长 1510 秒
2. 该段所有核心热工变量的变异系数 CV < 0.5%（P: 0.46%、TAVG: 0.00%、THA: 0.00%、VOL: 0.15%、PSGA: 0.00%、PWNT: 0.05%、QMWT: 0.05%）
3. 功率水平 100%，与 LOCA 事故初始功率一致
4. 变量名、采样率、仿真器完全一致，无对齐问题

**修正方法**：排除 WLR（泄漏流量，正常应为 0）、WECS（安注流量，正常应为 0）、WHPI（高压注水，恒为 0 无方差）等故障/安全系统变量，用 LOCA_1 恢复段的其他热工变量建 μ±3σ 阈值。不需要对数值做任何修正，只是选择哪些变量参与建阈值。

##### 修订后的阈值模块流程

```
输入：LOCA_1.csv
  │
  ▼
① 提取 t=520~2030s 的 100% 功率稳态段（152 点）
  │
  ▼
② 逐变量检查：
   - 变异系数 CV < 5% 且 非故障/安全系统变量 → 建 μ±3σ 阈值
   - WLR/WECS/WHPI 等 → 不建阈值，LOCA 中非零即异常
  │
  ▼
③ 用这些阈值标 LOCA 事故轨迹的异常
  │
  ▼
④ 报告：明确声明这是"100% 功率准 Normal 阈值"，
   基于 LOCA_1 恢复段，非真正正常运行数据
```

##### 局限性（必须如实声明）

- 只有 1 条轨迹（LOCA_1），无跨轨迹统计变异
- WLR 和 WECS 非零，说明系统仍有小破口泄漏和安注补偿，不是完美正常工况
- 但这已是现有数据条件下能得到的最好的 100% 功率基准，且比 Normal 轨迹的 100% 功率段（仅约 10 个点）多 15 倍样本

#### 解释生成（Phase 5.5）

把因果图边列表（方向、总效应、Bootstrap 频率）+ 本体知识 + 异常状态序列化为提示上下文，填充成结构化《根因分析报告》模板，必须显式写出方向不确定性。这对应论文的 causal graph prompt injection：让解释基于因果事实而非幻觉。

> **【2026-10-25 实现更新】LLM 解释生成已落地（DeepSeek V4.1-Flash）**

### 3.8 Algorithm 1 的适配：四指标 Bootstrap 与 f_e 的重新定义

#### 论文版 → 方案版

阶段 3 学的论文 Algorithm 1 只有一个稳定性指标 s = 1/(1+σ)（边权标准差越小越稳）。方案扩展为**四个指标**：

```
在训练集 80 条轨迹上重复 N=100 次：
  有放回抽 80 条轨迹 → 拼接时间点 → 跑 LiNGAM → 得 G_k、边权 w_k
对每条有向边 e（X→Y）：
  f_e      = X→Y 出现次数 / N                    （有向边出现频率，分母 N=100）
  s_e      = 1 / (1 + σ_e)                        （边权稳定性，自定义指标）
  方向一致率 = X→Y 次数 / (X→Y + Y→X 次数)         （分母：该变量对至少连一条边的重复数）
  符号一致率 = 主导符号次数 / X→Y 出现次数          （正效应/负效应是否稳定）
保留条件：f_e ≥ 0.5 且 s_e ≥ 0.6（初始阈值，要做敏感性分析）
```

**为什么需要四个**：单一 s_e 只看边权波动，会掩盖两类更致命的不稳定——方向翻转（这次 X→Y 下次 Y→X）和符号翻转（正效应变负效应）。物理上"压力升高导致流量升高"和反方向、负号是完全不同的机制陈述。

**两个小分母陷阱**：方向一致率的分母是"该变量对连过边的次数"，变量对很少连边时分母极小，方向率可能虚高，必须和 f_e 一起看；s_e 是自定义指标，受权重尺度影响，不是普适置信度。

#### ★f_e 的正确读法（方案定稿前修正的核心概念错误）

直觉上 f_e=0.9 很容易被读成"这条边有 90% 概率是真因果"。**这个读法在本数据上是错的**，推理链如下：

1. **DirectLiNGAM 对固定数据是确定性算法**——同一份数据跑两次，输出完全相同，没有拟合随机性；
2. **每个严重度只有一条仿真轨迹**——100 条轨迹与严重度 1~100 一一对应；
3. 于是第 k 次重采样中"轨迹 i 是否入选"完全等价于"**严重度 i 是否出现在本次训练集**"；
4. 因此 f_e 的变异几乎全部来自**训练集严重度构成的变化**，而不是"同一分布上算法重复拟合的波动"。

结论：

> **f_e 应读作"这条边对轨迹重采样（即严重度构成变化）的敏感程度"。f_e 高 = 边在多种严重度构成下都出现，是有价值的稳健性证据；但它既不是因果正确概率，也不是边的置信度，而且高 f_e 仍可能是所有严重度共享的遗漏混杂（见 3.11）造成的。**

**408 类比**：确定性编译器对同一份源码必然产出相同二进制；这里 Bootstrap 改变的不是"编译的随机性"，而是"这次选哪些严重度的源码进入编译单元"。f_e 衡量的是"换一批事故规格，这条边还在不在"，不是"这条边有多真"。

#### 两类稳健性必须分开报告

| 类别 | 回答的问题 | 看什么 |
|------|-----------|--------|
| ① 重采样稳定性 | 边是否随轨迹抽样消失 | 混合 f_e / s_e |
| ② 严重度稳健性 | 边的方向/符号在低/中/高严重度组间是否一致 | 三组**分别学图**的结果 |

二者不可互相替代。方案还提供可选的**分层 Bootstrap**（组内分别抽样、固定每次的严重度构成）作为低成本对照：分层 f_e 与混合 f_e 接近，说明边不依赖组间构成。

#### 严重度异质性的实测证据

WLR 在 t=300s 的取值跨严重度**非单调**：25%≈373 > 100%≈367 > 75%≈243 > 50%≈181 t/h。原因是不同破口尺寸在 t=300s 处于不同的喷放物理阶段（亚冷喷放/两相喷放、卸压程度不同）；P 在低组恢复、中高组持续下跌。所以方案要求：响应形态不同**不预设**因果结构不同（反之亦然），是否同构由分组学图实证；若组间方向不一致，主结论**按组分别报告**，混合图只作汇总——而"不一致"本身正是静态方法在异质瞬态下的边界证据。

#### 分组检查的正式定位：从"补充分析"提升为关键稳健性检查（2026-10-25 第二轮修订）

第二轮外审认为，这是三项意见中**对最终因果图解释影响最大**的一项，方案据此把分组检查提升到与轨迹级 Bootstrap 同级的必做项。核心原因是：主窗口内小破口轨迹已准稳态（P 恢复）、大破口轨迹仍在非平稳恶化（P 69→44 bar），把两种系统状态混做一张静态图，可能得到一张**不代表任何一组**的混合图。这不简单等于"违反 i.i.d. 的 identically distributed 就必然失败"，但混合图的解释边界必须由分组结果界定。

**两类结果必须分开陈述（实验前预注册、冻结）**：

| 结果 | 含义 | 能声称什么 |
|------|------|-----------|
| 混合主分析图 | 100 条（80 训练）轨迹混合学出的整体结构 | "在当前严重度构成与主窗口下算法得到的结构"，**不自动外推**为所有严重度的共同机制 |
| 严重度分组稳健性结果 | 低/中/高三组分别学图 | 界定混合图中哪些关系跨组成立 |

**三条解释规则（实验前冻结，看结果后不得改写）**：

1. **方向一致** → 报告为"跨严重度具有一定稳健性的候选关系"（仍只是候选，不是因果为真的证明）；
2. **方向翻转** → 如实报告异质性，**不强行从两个方向里选一个**，混合图中该边降级标注；
3. **某组无法稳定估计**（组内 f_e 普遍过低）→ 报告"该组证据不足"，**不得把"没学出来"解释成"该组不存在此关系"**。

**分组的能力边界（必须随结果一起声明）**：每组只有约 27 条轨迹（训练划分下约 21~22 条），有效样本量下降，**分组结果不一定比混合结果更准**——它的价值是揭示异质性、界定混合图的解释边界，而不是保证恢复真实图。另外要把两种风险分清楚：**轨迹级 Bootstrap 防的是伪重复，但它不消除单条轨迹内部的自相关**；分组检查防的是机制异质；两者都不解决 WLR↔P 反馈环的动态性。三者必须分别报告。

**408 类比**：混合图像拿"所有负载阶段（空闲/正常/压测）混在一起"训练出的性能模型——它描述的是平均工况，不代表任何一个真实阶段；分组重训像分阶段各建一张模型。但分阶段后每段样本变少、单张模型可能更不准，它真正的用途是告诉你"混合模型在哪些阶段是失真的"，而不是自动产出更正确的模型。

### 3.9 Algorithm 2 的适配：每次 Bootstrap 独立求逆

阶段 3 的公式原样保留：结构方程 X = BX + ε ⟹ 总效应 T = (I−B)⁻¹ = I + B + B² + …（Neumann 展开，直接/间接路径求和）。适配点在**计算口径**。

#### 核心陷阱：求逆是非线性操作

```
错误做法（禁止）：
  先把 N=100 次的边权平均成 B̄，再求一次逆 T̄ = (I − B̄)⁻¹

正确做法：
  对每次 Bootstrap 的完整矩阵 B_k 独立求 T_k = (I − B_k)⁻¹
  对每个候选上游 X，收集 100 个 T_k[P, X]，报告：
    中位数（点估计）、25%/75% 分位数（不确定性）、符号一致率
```

为什么不能先平均：矩阵求逆是高度非线性的函数，**平均后的逆 ≠ 逆的平均**（f(E[X]) ≠ E[f(X)]），而且平均边权会把时有时无的边糊成一条始终存在的弱边，凭空造出虚假结构。

**408 类比**：不能用"平均温度"代入物理公式算"平均饱和蒸气压"——非线性函数下，平均输入的输出不等于输出的平均。必须保留每次实验各自的结果，最后再汇总分布。

#### 上游排序

```
主排序分数：score(X) = |median(T_k[P, X])|     （单一目标变量 P）
同时报告：有符号中位数（物理方向）、IQR（不确定性）、符号一致率
```

- 论文是多目标异常 Y 求和，方案改为**单一目标 P**，且异常阈值不作硬过滤——上游变量可能自身没越限但仍是因（隐性根因）；
- 对"筛边后的稀疏图"算出的 T_stable 仅用于展示，**不得与 Bootstrap 总效应分布混用**（筛边改变了矩阵结构）；
- score 取绝对值中位数是方案的适配设计，非论文原公式，报告中明示。

#### 异常加权只能当消融

3.7 的分段阈值若存活，可算增强分数 |T| × (1 + α × 异常程度)（α 初值 0.3），但：

- **主排序始终是纯总效应**，核心结论只基于主排序；
- α 是工程经验值，且异常程度会与严重度共同变化，加权后排名上升不等于更接近根因；
- 增强排序只做敏感性分析（α ∈ {0, 0.1, 0.3, 0.5, 1.0}），报告与主排序的 Kendall τ / Top-K 重合率，差异大且无物理解释则不采用。

### 3.10 Algorithm 3 的降级：从"反事实验证"到"探索性一致性比较"

#### 为什么连名字都改了

阶段 3 学的论文 Algorithm 3 叫反事实验证：用留出数据比较 ΔB_pred = (a₂−a₁)·τ 与 ΔB_obs = E[B|A≈a₂] − E[B|A≈a₁]，误差小则边可信。方案保留全部计算形式，但把它**降级为探索性的"模型—观测一致性比较"**，并明确它不是实验成败标准。原因有三：

1. **观测条件均值差 ≠ 干预效应**。a₁/a₂ 组是按 WLR 观测值凑出来的，不是随机分组；严重度、时间阶段同时影响两组，ΔP_obs 里混着这些因素，不自动等于 do(WLR) 的因果效应；
2. **严重度梯度不自动构成准实验**——相邻严重度轨迹太相似，且无随机化；
3. **双向竞争的自然结果要如实报告**：若模型这次学的是 P→WLR，那么 WLR→P 的总效应 T[P,WLR]≈0，ΔP_pred≈0 是模型选择竞争方向的正常输出，不是"验证失败"，不许强行解释。

#### 两个执行细节

- **尺度统一**：τ、两个分位数 a₁/a₂、ΔP_obs 必须全部在同一标准化尺度上（验证集用训练集的 μ/σ 转换）；分位数取样固定为"Q₁/Q₃ 邻域内的点"一种口径并报告；
- **双划分**：划分一为随机轨迹 80/20，划分二为低中严重度训练/高严重度验证，两种结果分开报告。

**408 类比**：阶段 3 的类比是"去测试集验证预测涨 6 是否兑现"。这里要再退一步理解——连测试集里的"高输入组/低输入组"都不是实验员分配的，而是从自然运行记录里挑出来的，两组除了输入不同还带着很多别的差异。所以这个测试只能描述"模型与观测是否一致"，不能判定"因果是否为真"。

### 3.11 严重度：已观测但未控制的遗漏混杂（全方案最微妙的统计点）

#### 概念辨析：不是"未观测混杂"

方案定稿前专门修正了这个表述。严重度（文件名 1~100）是**概念上完全可以获得**的标签，所以它不是未观测混杂；准确说法是：

> 它是**已观测的轨迹级协变量，但没有进入 96 个传感器变量组成的建模矩阵**——不显式控制时，构成"遗漏的共同原因（omitted confounder）"：破口越大，P、WLR、VOL 等所有响应变量同时被驱动。

这个区分有实际意义：未观测混杂原则上无法调整；已观测协变量可以分层、对照。

#### 为什么不干脆把严重度加进模型？

两个硬性原因：

1. **它在轨迹内是常数列（零方差）**：一条 LOCA_25 轨迹的 121 个时间点，严重度恒等于 25。零方差变量无法作为 LiNGAM 的节点；
2. **对它回归残差化属于过度控制（overadjustment）**：严重度位于因果链最上游（注入量 → 一切响应），在堆叠数据上先消掉它的影响，会把"经由严重度传导的真实因果路径"一起阻断——等于把根因当噪声滤掉。

因此当前最合理的控制是 3.8 的**分层学图 + 组间一致性比较**，但方案同时声明它不彻底：组内仍有连续严重度梯度、每个严重度只有一条轨迹、无法估计同一严重度下的仿真随机波动。报告中不得宣称得到了"已调整严重度的因果效应"。

**408 类比**：严重度对单条轨迹而言是"编译期常量"，不是运行时变量——你没法把常量当特征喂给要求方差的模型。而"对上游因果断点残差化"像在性能分析时先把用户请求量的影响抹掉再比较模块耗时：请求量正是拖慢模块的真实上游路径，抹掉它就删掉了你要找的因果链。

#### 高容量模型不防混杂，可能放大它

这是 3.13 选择"用 GAM-ANM 而非完整 DiffAN"的理由之一：非线性模型容量更大，能把严重度梯度上的弯曲共同响应拟合得更"丰富"，产出更密的虚假边。即使用 GAM-ANM，也必须监控混合图相对分层图是否异常变密（混杂诊断指标）。

#### 由此产生的措辞纪律

方案统一要求结论表述为：

> "LiNGAM 在某窗口/某严重度组上**稳定识别出的有向关系**……"

禁止表述为"已证实/已验证的真实因果"。静态模型 + 非 i.i.d. 观测只能给出关联结构的识别结果及其跨重采样稳定性；物理方向的正确性由冻结的物理关系清单对照，**不由模型自己证明**。

### 3.12 没有标签怎么评估：三分类报告与 7 组消融

#### 三分类结果（三者不可相互替代）

| 类别 | 内容 | 回答的问题 |
|------|------|-----------|
| 1. 实现正确性 | 矩阵索引方向、总效应、四指标是否用两变量/链式小例子验证过 | 代码有没有算错 |
| 2a. 重采样稳定性 | 关键边的混合 f_e / s_e（读作对严重度构成的敏感度） | 换批事故还在吗 |
| 2b. 严重度稳健性（**第二轮提升为关键检查**） | 混合图与分组图作为两类预注册结果分开陈述；低/中/高组间方向、符号按三条冻结规则逐边裁定；另报划分种子敏感性 | 混合图代表谁、不代表谁 |
| 附. 模型假设诊断 | 偏度/峰度/JB 等非高斯性证据（描述性，**非开关**） | 假设被违背到什么程度 |
| 3. 物理一致性 | 与冻结的物理机制清单相符的程度；WLR↔P 单独报告 | 符合已知物理吗 |

核心纪律一句话：**稳定 ≠ 因果正确；符合物理直觉 ≠ 识别出真实因果结构。**

#### 7 组消融实验

| 实验组 | 设置 | 验证什么 |
|--------|------|---------|
| Baseline-1 | Pearson 相关性排序（无方向） | 因果方向的必要性（对应论文 0.33→0.92 的教训） |
| Baseline-2 | LiNGAM 直接出图（无 Alg1） | 稳定性筛选的价值 |
| Baseline-3 | LiNGAM + Alg1（无本体约束） | 纯数据驱动基线 |
| Baseline-4 | + 本体约束（无异常加权） | 本体约束的增量 |
| Baseline-5 | + 异常标记（无解释生成） | 异常标记的增量 |
| Baseline-6 | XGBoost 选出的变量集 | 标签泄漏风险对照 |
| **Full** | 全部 + Alg3 + 解释生成 | 完整神经符号流程 |

神经符号的三处关键对比（B3→B4 本体、B4→B5 异常标记、B5→Full 解释）要求**量化指标变化 + 图结构差异**（被删了哪些禁止边、标了哪些支持边），不能只展示"一张看起来更符合物理的图"。XGBoost 变量集只作对照：以事故类型为标签选特征最容易选到 WLR、P 这种"标签泄漏"变量，主实验坚持物理先验集。

**408 类比**：没有标准答案时，提交的不是一个分数，而是一份分维度测试报告——单元测试（实现正确性）、压力测试复现性（统计稳定性）、与规格说明书的符合性（物理一致性），三类测试各管一件事，互不替考。

### 3.13 非线性引擎选型与双引擎主线：GAM-ANM 替代完整 DiffAN

> **定位（2026-10-26 修订）**：原设计把非线性引擎设为 Day 4 门控的第二阶段对照。后经评审，原论文因果发现引擎本就是"LiNGAM/DiffAN"并列，忠实复现应将两算法**同时作为主线**。故将 GAM-ANM 提升为**主线双引擎之一**，与 LiNGAM 并列运行，结果经共识边 + RRF 融合作为主 RCA 输出。本节记录：为什么用 GAM-ANM 而非完整 DiffAN、以及双引擎如何融合。

#### 先纠正事实：DiffAN 到底是什么

方案核对原始文献后指出，**CausalTrace 正文对 DiffAN 的展开有误**：论文写的是 "Differentiable Causal Discovery with Attention"（可微注意力），但真实文献是 Sanchez et al., *Diffusion Models for Causal Discovery via Topological Ordering*, **ICLR 2023**（arXiv:2210.06201）——在非线性加性噪声模型下，用**扩散模型学习 Hessian** 识别叶节点做拓扑排序，剪枝还依赖 R 语言 cdt 工具链。复现以原文为准，并在报告中标注论文的这处不一致。（阶段 1 笔记沿用了论文的展开说法，读到这里要以方案的勘误为准。）

#### 为什么用 GAM-ANM 而非完整 DiffAN

1. **独立样本没有变多**：343~475 行都是同一次仿真的自相关时间点，有效单位仍约 100 条轨迹；两种算法都假设 i.i.d.，换模型不解决伪重复；
2. **DiffAN 的卖点用不上**：500 节点/10⁵ 样本的扩展性针对大 p 大 N，本研究 p≈15–20、N≈百条轨迹，扩散模型大参数在小有效样本下反而更易过训；
3. **假设同样不满足**：它不处理时间序列、输出仍是 DAG，**解不开 WLR↔P 反馈环**；热工关系近似线性、新息近似高斯时，它和 LiNGAM 会同时失去方向可辨识性；
4. **GAM-ANM 在 p≈14 下统计上更匹配**：广义加性模型 + 加性噪声模型，纯 Python 实现（pygam），无需 R/cdt 工具链，成本远低于训练扩散模型；
5. **忠实度足够**：GAM-ANM 与 DiffAN 同属非线性 ANM 可辨识性假设，能回答"非线性方法是否给出不同排序"这一核心科学问题，与 LiNGAM 形成线性/非高斯 vs 非线性 ANM 的对照。

> 论文同时报了 LiNGAM（20 边）和 DiffAN（15 边），但**没说明 RCA 指标基于哪张图**。本方案用共识边 + RRF 融合填补这一空白——不指定单方法为主图，让两种可辨识性假设互相验证。

#### 双引擎如何融合（关键方法学前提）

Algorithm 2 的 T=(I-B)⁻¹ **要求线性邻接矩阵 B，仅 LiNGAM 能提供**。GAM-ANM 不产出线性 B，因此融合分两层：

1. **边方向层**：两方法稳定边做三分类——共识边（方向一致，可信度最高）、冲突边（方向相反，标记不确定）、单边（仅一方法识别）；
2. **排序层**：用 RRF（Reciprocal Rank Fusion）合并 LiNGAM 总效应排序与 GAM-ANM 边际效应排序，`score(X)=1/(k+rank_L)+1/(k+rank_A)`，k=60。

**关键声明**：融合**不发生在矩阵求逆层**——不存在统一的 B_fused。RRF 融合排序是主 RCA 输出，两引擎各自排序作为子结果透明报告。

**结论纪律**：方法间一致**不是**因果正确性的证明（两者共享 i.i.d.、无环假设和同一个严重度混杂源）；不一致是关于**假设敏感性**的证据，按"线性/非高斯 vs 非线性 ANM 可辨识性差异"解读，不判输赢。无变量级真值时，不宣布哪种算法"更准"。

## 四、方案研读问答回顾

> 本方案不是问答产物，本节按阶段 1–4 的体例，把读懂方案必须跨过的八个问题整理成自学问答串。

### Q1：为什么不能把 12,100 行当成 12,100 个样本？

**对应章节**：3.4。同一轨迹相邻 10s 的时间点强自相关，是同一次事故的连续快照而非独立观测。独立单位是 100 条仿真轨迹；按时间点抽样会造成伪重复，并把共同时间趋势误判为因果边。一切抽样、划分、统计口径都以轨迹为单位。

### Q2：方案为什么反复强调"这不是根因分析"？

**对应章节**：3.2。NPPAD 的 96 个参数里没有"破口面积"这个注入变量，WLR/P 都是故障响应，无变量级根因标签可判对错。任务因此降级为"对目标 P 做上游因果定位，并用实验前冻结的物理关系清单做对照"。WHPI/WECS 这类安注动作是响应不是原因。

### Q3：LiNGAM 学出 P→WLR（而不是直觉的 WLR→P），算失败吗？

**对应章节**：3.3、3.8、3.10。不算。WLR 与 P 物理上双向耦合，DAG 只能选一个方向输出；方案把它当竞争假设，两个方向各自报告频率与稳定性，评估时也不把两个方向都算对。若学出 P→WLR，则 WLR→P 的总效应≈0、Algorithm 3 的 ΔP_pred≈0 是自然结果，不是验证失败。

### Q4：f_e=0.9 能说"这条边 90% 概率是真因果"吗？

**对应章节**：3.8。不能。DirectLiNGAM 对固定数据是确定性算法，每个严重度又只有一条轨迹，所以重采样的变异几乎全部来自训练集严重度构成的变化。f_e 的正确含义是"边对严重度构成变化的敏感度"，是稳健性证据而非因果置信度；高 f_e 仍可能源于所有严重度共享的遗漏混杂。

### Q5：本体确认"应该有"的边，为什么不能直接加进图？

**对应章节**：3.7。允许边只标记、不添加：手动加边后无法分辨一条边是数据学出来的还是规则注入的，图中的边就失去了数据可追溯性。本体只做两件事——对明确物理排除的禁止边删除并留痕，对数据已学到的允许边贴"本体支持"标签。

### Q6：为什么 Normal 阈值模块可能"整体退出"？退出了神经符号还成立吗？

**对应章节**：3.7。唯一一条 Normal 轨迹实测是功率漂移轨迹（PWNT 100%→40%、TAVG 310→299°C），对功率变量算分段 μ±3σ，分段均值变化本身就是真实功率变化，不构成正常波动带。若逐变量判定后可信变量不足，Phase 3.5 整体标记"数据不支持"并退出。主排序是纯总效应、不依赖该模块；神经符号的本体约束（1.5）与解释生成（5.5）仍在。

### Q7：为什么强调"每次 Bootstrap 独立求 T_k"，先平均 B 再求逆错在哪？

**对应章节**：3.9。矩阵求逆非线性，(I−B̄)⁻¹ ≠ median{(I−B_k)⁻¹}；平均边权还会把时有时无的边糊成虚假的常驻弱边。正确口径是逐次求逆、汇总 T[P,X] 的中位数与四分位区间。

### Q8：严重度明明知道（文件名就是），为什么不直接加进模型控制混杂？

**对应章节**：3.11。它在单条轨迹内是零方差常数列，不能作 LiNGAM 节点；且它是因果链最上游的注入量，对其残差化属于过度控制，会阻断经由它传导的真实路径。可行的最佳控制是分层学图 + 组间一致性比较，但组内仍有梯度、每严重度仅一条轨迹，不能宣称混杂已消除。

### Q9：要不要先做正态性检验，不通过就不用 LiNGAM？

**对应章节**：3.6（第二轮修订）。**不加这种硬门槛**。方向可辨识性依赖线性、无环、独立非高斯噪声一整组假设，不是"变量非高斯⇒方向可信"，也不是"检验没通过⇒LiNGAM 失效"。而且 12,100 个堆叠时间点强自相关、不独立，JB 检验的 p 值不能按 N=12,100 解释显著性。正确做法是把偏度/峰度/JB/分布图当**描述性体检**（再按严重度组×阶段交叉看），诊断结果只影响解读保守程度；即使非高斯性明显，时间依赖、反馈环、异质性仍可能使方向无意义。

### Q10：全局标准化可能把严重度信息编码进变量，为什么不直接改成轨迹内 Z-score？

**对应章节**：3.4（第二轮修订）。这个担心的前提不成立——标准化是逐变量的固定线性变换，严重度与变量的关联在原始数据中已存在，标准化不制造混杂。而轨迹内标准化反而有两个副作用：压掉轨迹间的绝对水平差异（"低组 155 bar / 高组 50 bar"正是严重度的物理表现），并放大准稳态轨迹的微小波动。所以保留全局 Z-score 为主（μ/σ 训练集一次性估计、各轮同口径防泄漏），轨迹内/组内口径只作敏感性对照，结果不一致时如实报告、不挑版本。

### Q11：分组学图如果某条边方向翻转或某组根本学不出来，结论该怎么写？

**对应章节**：3.8（第二轮修订）。按实验前冻结的三条规则写：方向一致 → "跨严重度有一定稳健性的候选关系"；方向翻转 → 报告异质性，不强选一个方向，混合图中该边降级；某组 f_e 过低无法稳定估计 → "该组证据不足"，不能写成"该组不存在此关系"。还要声明：分组后每组仅约 21~22 条训练轨迹，分组结果不一定比混合图准，它的作用是界定混合图代表谁、不代表谁。

## 五、关键总结

1. **方案的定位是迁移适配，不是严格复现**：三算法流水线（筛选→量化→验证）与神经符号三环节的骨架忠实于论文，但因数据集三个条件不成立（无变量级标签、非 i.i.d.、无领域知识库），每一层都做了有声明的降级。

2. **第一把钥匙：没有变量级 Ground Truth**。NPPAD 只有事故类型与严重度标签，96 个参数全是响应量。任务从"根因溯源"降为"对目标 P 的上游因果定位"，标准答案是实验前冻结的物理关系清单（预注册，不得事后改写）。

3. **第二把钥匙（最重要）：独立单位是 100 条轨迹，不是 12,100 个时间点**。相邻时间点强自相关，时间点级抽样是伪重复。轨迹级 Bootstrap、轨迹级 80/20 划分、禁止跨轨迹构造特征、有效样本量按 ~100 计，全部由此导出。

4. **WLR↔P 是理解全方案的物理戏眼**。压力驱动喷放、泄漏导致失压，是真实反馈环；DAG 只能输出单向，静态算法会随机选一臂。按竞争假设双向报告，学出任一方向都不算错，但评估时不把两个方向都算正确。

5. **主窗口 t=300~1500s 是主动选择不是数据限制**：等长 121 点、避开 110s 注入阶跃与 WLR 上升沿（共同趋势最易造假边）、研究对象限定为事故发展期。代价是小破口 P 已恢复、早期传播丢失；窗口冻结后不得看结果回调。

6. **防泄漏顺序是硬纪律**：先审计 → 先按轨迹 80/20 划分 → 仅训练集做标准化/学图/Bootstrap/定阈值 → 验证集只在 Algorithm 3 用一次。全量筛边再划验证集是明文禁止的反例。

7. **神经符号用轻量三件套落地但不删环节**：JSON 极简本体替代 RDF/Neo4j、LOCA_1 准稳态段数据驱动阈值替代专家公差、DeepSeek V4.1-Flash LLM + 因果图提示注入替代 LLaMA3-70B（无 key 时降级模板）；Phase 0.5/1.5/3.5/5.5 四个 ★ 环节必做。

8. **允许边只标记不添加，是知识不污染数据证据的关键**：最终图中每条边必须可追溯到数据；本体只删禁止边（留痕）、贴标签（允许边），绝不造边。

9. **Algorithm 1 升级为四指标**：f_e + s_e + 方向一致率 + 符号一致率，后两者专门捕捉方向/符号翻转。注意各指标分母口径不同，小分母会虚高。

10. **f_e 不是置信度**：确定性算法 + 每严重度单轨迹，决定了 f_e 的变异几乎全部来自训练集严重度构成变化，只能读作"边对严重度构成的敏感度"。重采样稳定性与严重度稳健性必须分两类报告。

11. **Algorithm 2 必须逐次求逆**：T_k=(I−B_k)⁻¹ 各算各的，再汇总 T[P,X] 的中位数/IQR/符号率；求逆非线性，禁止先平均 B 再求逆。主排序 score=|median(T_k[P,X])| 是纯总效应，异常加权只作探索性消融。

12. **Algorithm 3 被降级**：观测条件均值差≠干预效应，严重度梯度不自动构成准实验；它只是探索性的模型—观测一致性描述，不是成败标准，ΔP_pred≈0 可能只是竞争方向的自然结果。

13. **严重度是"已观测但未控制"的遗漏混杂**：文件名即标签但未进建模矩阵；不能作节点（轨迹内常数列）、不能残差化（过度控制上游断点）。分层学图是最佳可行控制但不彻底。结论措辞只能是"稳定识别出的有向关系"，不能说"已证实的因果"。

14. **因果发现是 LiNGAM + GAM-ANM 双引擎主线**（2026-10-26 修订）：论文引擎本就是"LiNGAM/DiffAN"并列，单列 LiNGAM 不够忠实；以 GAM-ANM 替代完整 DiffAN（p≈14 下统计更匹配、无需 R/cdt），两引擎结果经共识边 + RRF 融合为主输出。关键前提：T=(I-B)⁻¹ 仅对 LiNGAM 的线性 B 成立，融合发生在排序层与边方向层，非矩阵求逆层。方法间一致≠因果正确，不判输赢。

15. **扩展复用的原则是"算法带走、物理留下"**：统计与工程层跨事故复用；目标变量、变量集、冻结关系、本体、窗口必须随事故机理重建并重跑 Phase 0。12 类多轨迹事故可全套复用，5 类单轨迹事故禁止伪重复式硬做。

16. **（第二轮修订）非高斯性：加诊断，不加开关**。Day 1 新增偏度/峰度/JB 与分布图（按严重度组×阶段交叉看），但堆叠时间点非独立，JB 的 p 值不按 N=12,100 解释；观测变量非高斯 ≠ 方向必然可辨识，诊断只是假设证据、不是可辨识性证明，不设"检验通过才运行 LiNGAM"的硬门槛。

17. **（第二轮修订）标准化：指出风险，但不换成轨迹内 Z-score**。全局 Z-score 是逐变量固定线性变换，不制造也不消除混杂（关联在原始数据中已存在）；轨迹内标准化会压掉"低组 155 bar / 高组 50 bar"这类严重度的物理水平差异、放大准稳态轨迹的微小波动。故全局标准化为主（μ/σ 训练集一次性估计、各轮同口径），轨迹内/组内标准化只作敏感性对照，且不据此挑"好看"版本。

18. **（第二轮修订，三项中对图解释影响最大）严重度分组提升为关键稳健性检查**：混合主分析图与分组结果预注册分开陈述；三条规则实验前冻结——方向一致→跨组候选关系、方向翻转→报告异质不强选、某组估不出→证据不足≠关系不存在。分组后每组仅约 21~22 条训练轨迹，**分组结果不一定更准，价值在于界定混合图的解释边界**；伪重复、轨迹内自相关、机制异质、反馈环是四种不同风险，必须分别报告，不能用一个处理抵消另一个。

## 六、延伸阅读与下一步

### 本方案暴露的方法学短板 → 真正的时序因果方法

本方案用静态 LiNGAM 做静态近似，而 WLR↔P 反馈环、时间点自相关本质上是动态问题，后续可重点补：

- **PCMCI / PCMCI+（Runge et al.）**：专为带强自相关的时间序列设计的因果发现，用滞后条件选择处理时间依赖——这正是本方案"轨迹级 Bootstrap"绕过而非解决的问题；
- **Granger 因果、向量自回归（VAR）、动态贝叶斯网络（DBN）、结构时变模型**：能显式表达滞后效应与反馈环（WLR_t → P_{t+1} → WLR_{t+2}），把"环"展开成时间下标上的 DAG；
- **LiNGAM 家族**：DirectLiNGAM（确定性直接解法，本方案实际使用）、VAR-LiNGAM（时序版）、LiNGAM for time series；
- 伪重复（pseudoreplication）概念本身值得补：生态学实验设计中对"重复单位"的经典讨论。

### 因果推断统计纪律

- **分层 Bootstrap（stratified bootstrap）** 与聚类标准误（cluster-robust SE）：处理"组内相关"数据的标准工具；
- **过度控制/碰撞节点（overadjustment / collider）**：为什么不该对上游因果变量残差化；后门准则中"哪些变量该控制"的判定；
- **有效样本量与自相关时间**：用 ACF 衰减、有效样本量 N_eff 的估算（Day 1 必做项）。

### 核工业 RCA 方向的结合思考

- 12 类第一梯队事故提供了天然的多场景试验床：同一算法引擎产出的稳定边结构差异，能否作为各事故机理的"因果指纹"？
- PCTRAN 可自定义注入参数：未来能否为同一严重度跑多条带随机扰动的重复仿真，获得当前缺失的"同严重度重复"，从而把分层控制升级为真正的分层估计？
- 剂量变量（Dose_csv_data）在 SGTR 类事故中首次相关——跨回路传热 + 放射性传导链的因果图如何冻结，是 SGTR 扩展时最有研究价值的部分；
- 解释生成已接入 DeepSeek V4.1-Flash LLM，通过"因果图提示注入 + 忠实性校验（正则匹配 median_T 数值）"双保险防幻觉；后续可对照论文 ROUGE-1 0.56→0.91 的消融逻辑设计更系统的解释质量评测。
