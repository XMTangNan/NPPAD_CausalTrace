## 0. 给专家看的说明

**需要您做什么**

对下表四类事故，逐类回答两个问题（只做排除，不要求指出唯一根因）：

1. 在这类事故中，**哪些参数/部件必然先响应**（事故发生后、主窗口内最先出现方向一致变化的量）？
2. 在这类事故中，**哪些参数/部件不可能先响应**（按机理它不会因该事故而第一时间变化）？

其余变量可留空或标"不确定"，留空不会被当成"可能"。

**判断粒度**

- 可以只填到**子系统级**（例如"二回路给水：必然先响应"），不必逐个变量给判断。
- 也可以只填其中一档（只填"不可能先响应"同样有用）。
- 允许写"取决于破口位置/尺寸"这类条件性说明，填在每类的备注栏。

**大概耗时**

每类约 15 个候选变量，按类勾选；若按子系统整段判断，单类约 15–30 分钟。

**您的判断会被怎么使用**

- 只用于**排除性核验**：把模型的头名输出与您给的"必然先响应/不可能先响应"集合比对，报告"覆盖率"与"违反率"两个诊断值。
- **不用于调参、不参与训练、不会反向影响模型**；也不会被写成新的"人工真值表"用于准确率主张。
- 您的判断会以类为单位、附上您的署名与日期存档；未填写的类在报告中标记为 `pending_expert`，不按 0 计。

## 6. 专家判断如何变成指标

### 6.1 输入形态（建议的机读格式）

```json
{
  "class": "LOCA",
  "reviewer": "<姓名>",
  "date": "YYYY-MM-DD",
  "granularity": "variable",
  "labels": {"WLR": "NFR", "P": "NFR", "PSGA": "IFR", "RHRD": "IFR"},
  "subsystem_labels": {"二回路给水": "NFR"},
  "notes": "条件性说明原文"
}
```

- `labels` 与 `subsystem_labels` 可只给其一；同一变量同时出现在两处时以 `labels` 为准。
- `granularity` 取值 `variable` / `subsystem` / `mixed`，决定 §6.6 的折算方式。
- 建议每类一个 JSON，文件名 `expert_<类>_<日期>.json`；本表可以先纸质勾选，再由人工誊录。

### 6.2 指标一：必然先响应覆盖率（NFR-Cov）

**定义**：模型头名（top-1）落在专家 `NFR` 集合内的比例。

```
NFR-Cov(类) = |{ i : top1_i ∈ NFR_set(类) }| / D_NFR(类)
```

- `D_NFR(类)` = 该类中**专家至少给出一个 `NFR` 标注**的检验条数。
  - 若专家只给类级集合（不区分条），`D_NFR(类)` = 该类有模型输出的条数（LOCA/SGATR/FLB 各 20 条）。
  - 若专家按时间窗或严重度分档给了不同集合，则按"该条所属档的集合"判定，分母仍为该类条数。
- `D_NFR(类) = 0` → 该指标记 **`pending_expert`**（不是 0，也不进汇总）。
- 辅助值（同分母）：`NFR-Cov@3` = top-3 中至少一个落在 `NFR` 集合内的比例，仅作参考，不作主张。

**这不是准确率**：分母只覆盖专家愿意下判断的部分；`NFR` 集合是多值集合，
不存在"唯一正确答案"，命中即"落在可接受集合内"，不是"判断正确"。

### 6.3 指标二：不可能先响应违反率（IFR-Viol）

**定义**：模型头名落在专家 `IFR` 集合内的比例。

```
IFR-Viol(类) = |{ i : top1_i ∈ IFR_set(类) }| / D_IFR(类)
```

- `D_IFR(类)` = 该类中**专家至少给出一个 `IFR` 标注**的检验条数（规则同 §6.2）。
- `D_IFR(类) = 0` → **`pending_expert`**。
- 该值越小越"不违反机理"，但**不能**反过来说"越小越准确"：`IFR` 只覆盖被专家明确排除的那部分变量。

**这不是准确率**：它只检验"是否踩到被排除项"，与"是否找对根因"不是同一件事；
一个模型可以既不违反 `IFR`、也不落在 `NFR`（此时 `NFR-Cov` 也不加分），
两个指标也不是互补事件，`NFR-Cov + IFR-Viol` 不等于 1。

### 6.4 `pending_expert` 的记法与汇总

| 情形 | 记法 |
|---|---|
| 该类完全没有专家输入 | 两个指标均 `pending_expert`，汇总时**不参与**均值，单列 `n_classes_pending` |
| 该类只填了 `NFR` | `NFR-Cov` 出数，`IFR-Viol = pending_expert` |
| 该类只填了 `IFR` | `IFR-Viol` 出数，`NFR-Cov = pending_expert` |
| 变量留空 / `PFR` / `UNK` | 不影响任何分母；该变量既不算命中也不算违反 |

汇总只在"非 pending 的类"上取均值，并**同时印出参与汇总的类数与类名**，禁止用 0 填补缺失类。

### 6.5 为什么这两类指标不是准确率（汇总结论）

1. **分母不是全体样本**，而是"专家给了判断的子集"，随专家标注量变化，不可与任何 `n=60` 类指标同表比较。
2. **没有唯一答案**：`NFR`/`IFR` 是集合约束，不是单值标签；"命中集合"≠"答对"。
3. **只覆盖排除性信息位**：不评价排序质量（第 2 名及以后）、不评价数值偏差、不评价因果结构。
4. **两指标非互补**：既不 `NFR` 也不违反 `IFR` 的情况大量存在。
5. 因此报告中的措辞只能是"专家判据下的覆盖率 / 违反率（诊断项）"，**不得**写作 accuracy / precision / recall，
   也不得据此给出"方法 X 更准"的表述。

### 6.6 粒度折算（变量级 / 子系统级）

- 专家给 `subsystem_labels` 时，把模型 top-1 变量按 `variable_dictionary.yaml` 的 `subsystem` 字段映射到子系统再判定，
  结果记 `level = subsystem`；变量级与子系统级结果**分列**，不混算。
- 同一类既给了变量级又给了子系统级：以变量级为准（`granularity = mixed` 时逐条按"该变量是否有变量级标注"回退）。
- 子系统映射的唯一来源是 `variable_dictionary.yaml`（96 项）；若某个模型输出变量不在该字典内，该条记 `unmapped`，不进分母。
