# NPPAD × CausalTrace 项目方案阐述

> **项目**：NPPAD × CausalTrace 神经符号因果签名 RCA
> **日期**：2026-10-27

---

## 一、项目定位

在 NPPAD 核电仿真数据集上，复现 CausalTrace（AAAI-26）论文的**神经符号因果分析骨架**，验证"跨事故类型根因识别 + 事故内变量传导链解释"的可行性。定位为**变体复现**，非严格复现。

---

## 二、数据集能力边界（待确认）

**数据集**：[NPPAD](https://github.com/thu-inet/NuclearPowerPlantAccidentData/tree/main)（清华核研院 PCTRAN 仿真）

### 能做的

1. **跨事故类型识别**：给定一条异常轨迹，判定其事故类型——文件夹名即 Ground Truth。
2. **事故内变量传导链解释**：识别事故类型后，给出该事故内部从故障指示器（marker）到系统症状的变量传播路径，并用 LLM 生成自然语言解释。

### 本阶段不支持的

- **事故间演化因果链**（A 事故导致 B 事故导致 C 事故）：NPPAD 每个文件仅注入**单一始发事件**，无事故叠加样本，数据结构不支持；本阶段不纳入。

### 数据防泄漏说明

文件夹名仅用于标签生成与数据划分，不进入特征、因果图路径或 LLM 提示词；采用轨迹级划分（整条轨迹进训练或测试），避免同轨迹泄漏。

### 结论

RCA 粒度为 **"事故类型（直接根因）+ 事故内传播链（间接根因链）"**，非"事故间演化溯源"。

## 三、与原论文的方法骨架对比

以下为方案设计，与原论文方法骨架逐项对比。

### 3.1 采用的论文核心骨架

| 论文组件 | 本项目对应 | 采用情况 |
|---------|----------|---------|
| **神经符号三环节** | ①本体约束因果发现 ②异常变量筛选 ③LLM解释+因果图提示注入 | 全部采用 |
| **Algorithm 1** Bootstrap 稳定性 | 四指标 Bootstrap（出现频率 / 边权稳定 / 方向一致率 / 符号一致率） | 扩展采用 |
| **Algorithm 2** 总因果效应 T=(I−B)⁻¹ | LiNGAM 引擎保留总效应矩阵口径（T 列即传播签名）；GAM-ANM 引擎输出边际效应排序。二者统一为"传播签名排序向量"，GAM 边际效应不称为总因果效应 | 公式保留，口径区分 |
| **Algorithm 3** 反事实验证 | 签名质量门控（决定签名是否可用/降权，不进入分类融合分） | 降级为门控，不进分类分 |
| **双引擎设计**（LiNGAM / DiffAN 并列） | LiNGAM + GAM-ANM 双引擎 | 架构保留，引擎 B 替换 |

**门控与匹配的关系**：Algorithm 3 门控在签名构建阶段执行，决定该签名是否可用；E3 因果反演是测试阶段的匹配证据之一。门控失败的签名降权或弃用，不触发测试侧弃权。

### 3.2 三处取舍及理由

| 论文原方法 | 本项目取舍 | 取舍理由 |
|-----------|----------|---------|
| **DiffAN**（可微因果发现+注意力） | → **GAM-ANM**（广义加性模型+加性噪声） | 数据规模小，深度模型在小样本上方差过大；GAM-ANM 同属 ANM 可辨识性范式，更稳定可解释。架构可插拔，有条件可换回。 |
| **RDF 知识图谱 + Neo4j 过程本体**（专家定义公差） | → **极简三层本体**（变量→子系统→关系）+ **数据驱动 μ±3σ 阈值** | 无核电领域 RDF/Neo4j 知识库，无专家定义的运行公差。用轻量件实现同等功能，效力降级为"探索性异常评分"。需领域专家合作才能补全。 |
| **LLaMA3-70B** | → **DeepSeek V4.1-Flash** | 可访问性，功能对等。仅需改 API 端点即可换回。 |

### 3.3 数据流图对比

**原论文 CausalTrace 数据流：**

```
传感器时序数据
    │
    ▼
数据加载 + 特征选择
    │
    ▼
因果发现引擎（LiNGAM / DiffAN）
    │
    ▼
[神经符号①] 本体约束（禁止边删除 / 允许边标记）
    │
    ▼
因果图（DAG）
    │
    ├──► Algorithm 1：Bootstrap 稳定性筛选
    │
    ├──► Algorithm 2：总因果效应 T=(I−B)⁻¹
    │
    ▼
RCA 模块（总效应排序 + 公差范围筛选异常变量）
    │
    ▼
根因候选排序
    │
    ▼
[神经符号③] 因果图提示注入 + 知识图谱 → LLM 生成自然语言解释
    │
    ▼
根因分析报告
```

**本项目数据流：**

```
多事故轨迹
    │
    ▼
【Phase R0】数据审计 + 轨迹级划分 + 共享准 Normal 基线
    │
    ▼
【Phase R1】逐类构建因果签名 Σ_k（类 × 严重度组 模板）
    │   ├── LiNGAM 引擎：因果图 + 总效应传播签名
    │   └── GAM-ANM 引擎：因果图 + 边际效应传播签名
    │
    ▼
[神经符号①] 本体约束（禁止边 / 允许边 / 未知边 三分类）
    │
    ▼
【Phase R1.5】Algorithm 3 反事实验证（签名质量门控）
    │
    ▼
【Phase R2】匹配器
    │   ├── E1：marker 激活证据
    │   ├── E2：异常模式相似度（神经符号② 数据驱动阈值筛选）
    │   └── E3：因果反演（溯因诊断：症状→哪类签名最相容）
    │
    ▼
弃权机制（无异常症状 / 置信度低 / 歧义 → 弃权）
    │
    ▼
事故类型识别（直接根因）
    │
    ▼
【Phase R5】传播链（marker→症状 BFS + 双引擎排序）
    │
    ▼
[神经符号③] 因果图提示注入 + 本体知识 → LLM 生成解释
    │   （LLM 仅做解释，不参与因果发现与根因排序）
    ▼
根因分析报告
```

> **Phase 编号说明**：R0 审计划分 → R1 签名构建 → R1.5 反事实验证门控 → R2 匹配器 → R5 传播链解释。R3/R4 为方案预留的评估/消融阶段，本对接稿暂不展开。

**关键差异**：
- 论文 RCA 是"给定目标异常，按总效应排上游变量"；本项目反转为 **"给定症状向量，问哪类事故签名最相容"**（溯因诊断）
- 新增 **MASKED 条件**（marker 掩蔽，模拟传感器缺失）、**D0 门控**（因果增量判据）、**弃权机制**——这些是论文没有的设计

## 四、实验范围

本阶段选取 **LOCA（一回路失水）、SGATR（SG-A 传热管破裂）、FLB（给水管道破裂）** 共 3 类事故开展验证。

选取理由：这三类构成以蒸汽发生器为界面的"装量丧失"故障谱系，源头分处一回路/传热管/二回路，高严重度下症状有交集——正适合检验因果签名能否把共享症状还原到不同源头。该分类仅用于实验设计，不作为核电领域本体结论。

### 术语

| 术语 | 含义 |
|------|------|
| NPPAD | 核电仿真事故数据集 |
| RCA | 根因分析 |
| LOCA | 一回路失水事故 |
| SGATR | 蒸汽发生器 A 侧传热管破裂 |
| FLB | 给水管道破裂 |
| marker | 故障指示器变量（每类事故唯一激活） |
| E1/E2/E3 | 三层匹配证据：marker 激活 / 异常模式相似度 / 因果反演 |
| D0 | 因果增量门控实验（判断 E3 是否优于基线） |
| MASKED | 测试侧掩蔽 marker 的条件 |
| Σ_k | 事故 k 的因果签名 |

## 五、方案设计的已知局限与风险

- 静态 DAG 无法处理 WLR↔P 等动态反馈环；时间点强自相关经轨迹级 Bootstrap 缓解但未消除。
- 仿真器近似确定性 + 严重度扫描，统计功效有限；结论限定 PCTRAN 仿真与当前事故类型范围，不向真实电厂外推。
- 双引擎排序冲突时，按共识边优先、冲突边标注不确定性处理，不强行指定单一引擎方向。
- 共享准 Normal 基线用事故 sev-1 恢复段池化构建，低严重度事故除 marker 外症状极弱，MASKED 条件下设计预期为弃权（不硬猜）。
- LLM 解释存在幻觉风险，已通过忠实性校验（变量幻觉检测 + 数值对拍）降级到代码模板兜底。
