## 0. 根因定义（项目级规则）

**根因 = 在给定事故类别内、众多变量相互传递影响的链条中，最先动起来的那个/那几个变量。**

- 换句话说，根因是"**传导起点**"，不是"影响面最大"或"数值最异常"。
- 本项目排序量取 `T=(I−B)⁻¹` 的列和（总影响力），它衡量"谁影响全局最多"。列和越大越可能位于
  链条上游，因此它是"起点性"的**代理度量**，语义与上述定义一致；但代理不等于确认。
- 因此，本项目的报告**可以直接写"根因"**，但必须同时声明：这是**以传导起点为定义的根因**，
  而不是"经现场证据确认的唯一物理起因"。
- 排序靠前不等于根因成立：当图证据与知识证据方向相反时，报告必须原样披露冲突，不得把响应量
  写成根因（知识条目中 `can_be_root=false` 的约束仍然有效）。

## 1. 任务定义与边界

### 1.1 做什么

输入一条事故轨迹（事故类型已知、严重度分档已知），输出：

1. 该类型内部、**变量级**的根因排序 Top-5（每个变量附名次、总效应、入/出度、可达规模）；
2. 从 Top-5 出发的传导链（每根变量至多 20 条路径，单路径 ≤4 条边）；
3. 一份固定五章的解读报告：图结构 → 逐候选判定与依据 → 冲突与不确定 → 结论 → 局限与复现。

### 1.2 不做什么

| 不做 | 原因 |
|---|---|
| 事故类型分类 / 模板检索 | 类型与严重度是输入条件，不是待预测量 |
| 严重度估计 | 同上；三档严重度由数据给定 |
| 跨事故类型比较"谁更危险" | 各类的变量集、窗口、量纲不同，排序不可跨类比 |
| 跨模板比较"谁更准" | 不同模板的真值集大小与可达性不同，见 §4 |
| 主张准确率 / 命中率 | **没有独立真值**，见 §4.1 |

### 1.3 读者应如何理解 Top-5

Top-5 是在"当前这张因果图 + 当前知识条目"约束下，**最可能驱动异常的过程变量**，其含义是
"可解释、可复核的假设排序"，不是"正确答案"。报告里每个候选都写清了图依据（哪几条边、什么系数）
与知识依据（哪条机理条目），以及图与知识冲突时冲突在哪。

### 2.1 数据提供了什么、没提供什么

- 提供：逐时刻的过程变量时间序列；事故类型；严重度（如"破口面积 % of 100 cm²"）。

## 3. 方法主线

```
原始轨迹
  → 变量选取（四阶段 + V0–V7 门控）          → variable_sets/
  → 知识融合（K1 字典 / K2 物理关系 / K3 故障模板）
  → 因果发现（LiNGAM + bootstrap + 稳定边）    → signatures/
  → 溯源排序（T=(I−B)⁻¹，Top-5）               → tracing/
  → 传导链与图谱                               → graphs/
  → 解释报告（模型判定 + 规则兜底）             → reports/
```

### 3.1 变量选取：四阶段漏斗 + V0–V7 门控

**四个阶段**

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 1 候选池 | 以变量本体表为底，纳入论文锚定变量与该事故的触发/关键响应；保留原始测点 | 候选清单 |
| 2 冗余与打分 | 对 \|r\| ≥ 0.99 的精确重复测点去重；按综合得分排序 | 有序候选 |
| 3 数量与覆盖 | 控制变量数在 15–25；保证每个相关子系统至少 1 个变量 | 初选集 |
| 4 门控与冻结 | 逐项过 V0–V7，冻结变量集并记录每个被剔除变量的剔除阶段 | 变量集 + 剔除记录 |

**V0–V7 各查什么**

| 门 | 查什么 | 不通过怎么办 |
|---|---|---|
| V0 论文锚定 | 锚定变量要么入选、要么有剔除记录（`stage1_or_missing` / `deduplicate` / `vif_iter` / `n_max_trim`） | 缺记录才算失败；剔除本身不算失败 |
| V1 变量数 | 15 ≤ p ≤ 25（诊断档 `selection_profile=wide` 放宽为 15 ≤ p ≤ `n_train_trajectories`，仅作诊断、不进入论文数字） | 按得分补充或剔除 |
| V2 子系统覆盖 | 相关子系统均 ≥1 变量 | 强制补入该子系统最高得分变量 |
| V3 共线性 | 非保护变量的最大 VIF < 500；保护变量（触发/关键响应/子系统代表）逐项披露、不参与判定 | 迭代剔除非保护变量；保护变量按物理约束保留 |
| V4 触发变量 | 必须包含该事故的触发变量 | 强制保留 |
| V5 物理链完整 | 关键响应是否都有代表变量；\|r\|≥0.99 的重复测点对可互为等价代表 | 非等价代表的缺失判失败并强制补入 |
| V6 可复现 | 同数据、同参数下选取结果一致 | 重跑核对 |
| V7 非高斯诊断 | 记录 \|skewness\|>0.5 的变量占比（LiNGAM 的前提检查） | 仅记录、不阻断 |

**列序固定**：进入因果发现前，变量一律按变量名字母序排列。原因是 LiNGAM 的逐变量回归对输入列序敏感，
不固定会让 Top-1 依赖选择器内部输出顺序，无法被第三方复算。

### 3.2 知识融合：三层知识 + 本次补充的机理条目

| 层 | 内容 | 用途 |
|---|---|---|
| K1 变量字典 | 每个变量的中文名、单位、所属子系统（字段为 `meaning / subsystem / unit`） | 解释与报告措辞；不参与打分 |
| K2 物理关系 | 5 条教科书级关系（如装量损失、ECI 触发、传热管破口旁路等），每条给出期望方向与禁边规则 | 与稳定边做三态核对：`violated` / 一致 / `not_violated` |
| K3 故障模板 | 每类事故的期望传导链（边序列）与期望符号方向 | 计算覆盖率、反向边、缺失边 |

**禁边规则（硬约束）**：marker（触发指示器）不得被其它变量指向；响应量不得写成根因。
这两条同时约束因果图的解释与报告措辞。

**本次补充的机理条目**：针对 5 个在图上"看起来像枢纽"的变量（慢化剂温度反应性、稳压器水位、
安全壳压力、安全壳温度、一回路压力），补了 5 条机理条目，逐条标注"该量是响应、可作传导节点、
不可作根因"。这 5 条**只进入解释证据包**，不参与排序融合，且状态为**待专家确认**
（`pending_expert`）——它们是人工按物理机理补充的，不是数据结论。

### 3.3 因果发现：LiNGAM + bootstrap + 稳定边

1. 每个模板在学图窗上拟合 **DirectLiNGAM**（单引擎），得到直接效应矩阵 B；
   - **标准化口径（2026-11-11 起）**：每个模板用其训练段（全部训练轨迹的学图窗）池化
     均值/标准差，对**全部建模变量**统一标准化；不含物理下限、不做 z 截断，触发指示器
     不再单列。稳定边判据、截断阈值与排序规则不变。
2. 做 bootstrap 重采样（正式档 100 次 / 测试档 5 次），逐次拟合；
3. **稳定边判据**：同一条有向边在重采样中同向出现的比例达到设定阈值即判稳定；边权取
   重采样中位数（`weight_median`），同时记录出现比例（`consensus_rate`）；
4. **截断**：|B| > 5.0 的元素视为共线性伪影并截断，记录截断条数与截断比；同时输出
   3.0 / 5.0 / 10.0 三档敏感性；
5. 输出 `signatures/{K}_{g}.json`：变量清单、稳定边（含系数与出现比例）、截断证据、
   条件数、以及该模板的运行参数。

**口径说明**：当前为单引擎，不提供多引擎共识；稳定边是"同一引擎下的重采样稳定性"，
不等于跨算法共识。测试档（5 次）**不足以**支撑任何稳定性表述。

### 3.4 溯源排序：总效应 + 排序键

1. 用稳定边的 `weight_median` 重建直接效应矩阵 B，计算总因果效应矩阵 **T = (I − B)⁻¹**；
2. 定义"效应变量"= 终端节点（出度 0）+ marker（症状端）；
3. 对每个候选变量，**总效应得分** = 它到全部效应变量的总效应绝对值之和；
4. 排序键（依次比较）：`(-总效应, 入度升序, 加权可达规模降序, 可达规模降序, 出现比例降序)`；
5. **注入变量（触发通道）作为普通候选参与排名**，不做遮蔽——它出现在榜首是允许的，
   因为触发通道本身就是最上游的候选；
6. 输出 `tracing/root_candidates_{K}_{g}.json`：全变量总效应、Top-5、名次、B 截断证据、条件数。

> 排序键里的"入度升序"是对"上游优先"的弱偏好，不是物理约束。它在稠密图上会被出度结构放大，
> 见 §6 已知问题 ①。

### 3.5 传导链与图谱

- 从 Top-5 出发枚举路径：单路径 ≤4 条边（≤5 个节点），每根变量至多 20 条，按总效应贡献排序；
- 输出自包含 HTML 图谱（内联 SVG，无外部依赖，可直接双击打开）：节点按变量名与子系统着色，
  稳定边带方向与系数，Top-5 高亮，路径可逐条查看。

### 3.6 解释报告（第八步）：模型判定稿 + 规则兜底

每份报告由**模型判定稿**与**规则兜底**两条路径之一生成，章节顺序固定为：

| 章 | 内容 | 由谁写 |
|---|---|---|
| 一 图结构与 Top-5 | 变量数、稳定边数、bootstrap 次数、排序键、Top-5 名次表 | 程序（算法给定） |
| 二 逐候选判定与依据 | 每个候选：支持 / 部分支持 / 不支持 / 无法判断 + 图依据（边与系数）+ 知识条目 + 一句话机理 + 冲突 | **模型** |
| 三 冲突与不确定项 | 程序预计算的冲突（响应量不可作根因、反向边、缺失边）+ 模型识别的冲突 + 缺哪条证据；3.4 节列出"图为何这样排"的程序诊断（双向边对、与期望链相反、只出不进的枢纽、量级最大的边） | 程序 + 模型 |
| 四 结论 | ≤120 字，只复述名次与判定；若五候选全部无支撑/无法判断，必须结合 3.4 的诊断说明图为何这样排 | **模型** |
| 五 局限与复现 | 单引擎/截断/覆盖不全/σ 口径、lineage、复现命令、证据包指纹 | 程序 |

**硬约束**：变量只能来自该模板候选；数值只能来自证据包；机理必须引知识条目 id；不得重排；
**候选集状态只能引用证据包**（"未进前五"不得写成"不在候选集"）。
任一校验不过（越界变量、编造数值、知识 id 不存在、擅自重排、调用失败），整份**回落规则稿**，
抬头写"未经模型判断"，失败原因写入同一目录的证据附件 json。人读正文是 `.txt`，
`llm_explanation_{K}_{g}.json` 只是证据附件（证据包 + 校验记录）。

## 4. 评测口径

**结论先说**：本工作**不主张准确率**，主表只保留"结构健康度"（描述性）与"解释忠实性"，
机理一致性标为**待专家确认**；稳定性一类推断量已取消，不再产出。

### 4.1 为什么不主张准确率：没有独立真值

数据只给事故类型与严重度，**没有变量级根因标注**。所有"真值"都是按机理人工指定的假设
（例如"LOCA 的根因应在装量损失链的上游"），而且这些假设与候选变量集同源、存在构造关联。
因此任何命中类指标（Hit@k、MRR、P@k、Recall@k、AP@k、Jaccard@k）测到的都只是
**"与人工假设的一致度"**，不是准确率；不同模板的真值集大小还不一样（1 个 vs 3 个），
分母本身不可比。这些指标已整体撤出结果层，只作内部留档。
**论文正文不展开；附录只写一句："命中类指标已评估，但不作准确率主张。"**

### 4.1.1 三道质量门：只作记录，不构成通过

变量选取与建图过程中的 VIF 门（阈值 500）与条件数门（阈值 10000）**保留字段，但不构成
"质量合格"的判定**：前者阈值同时是迭代停止条件，非保护变量的最大值恰好卡在阈值下方；
后者截断后实测最高 1054.8，9/9 全部通过。两门都不提供区分信息，**不是质量合格证**。
报告与材料引用它们时，只能陈述"数值多大"，不得写"通过/稳定"。

### 4.2 三条系统性前提

**① 无独立真值。** 真值是机理假设而非标注，且与我方候选集存在构造关联；因此只能称
"一致度"。若有人把它当成绩单，等于用假设验证假设。

**② 样本不独立。** 同一模板下 20 条轨迹共享同一张图、同一组稳定边，不是 20 次独立试验；
在因果通道上，全部 run 只产生 9 个不同排序（每类 3 个）。按"60 条独立样本"算出的
置信区间被系统性压窄，跨模板、跨类比较都没有统计基础。

**③ 门槛不可失败。** 三类质量门在结构上不会失败：共线性门的上限同时是迭代的停止条件，
非保护变量的最大值恰好卡在阈值下方；条件数门的阈值没有来源、截断后 9/9 全部通过；
跨组一致性指标与随机基线几乎重合。也就是说，"通过质量门"不提供任何区分信息。

### 4.3 主表实际保留什么

| 类别 | 内容 | 读法 |
|---|---|---|
| 结构健康度（描述） | 节点数、稳定边数、边密度、条件数原值、被截断边数、截断比 | 只陈述"图有多密、条件数多大"，**不写"通过/稳定"** |
| 机理一致性 | 违反率 / 覆盖率 | **待专家确认**：排除性判据与统计协议尚未定稿，当前不复用历史数字 |
| 解释忠实性 | 变量/数值/知识 id 三项校验是否通过、是否回落规则稿 | 可复核；逐份记录在证据附件 |

**稳定性一类推断量已取消，不再产出。** 早期曾打算统计"三组 Top-1 是否相同""跨组 Top-5 重叠"
这类指标，现已判定这类统计没有实际意义，**不做、也不列为待办**（用户裁决 2026-11-11）。
因此报告、汇总页与论文中都不会出现"稳定/不稳定"的判词，只有单组（单模板）的排序与判定。

## 5. 运行与复现

### 5.1 两个档位

| 档位 | bootstrap 次数 | 用途 | 限制 |
|---|---|---|---|
| 正式档 `spec` | 100 | 出报告、作为交付 | 唯一可引用档位 |
| 测试档 `reduced` | 5 | 冒烟、调试、开发 | **产物不得引用**、不得指向 `latest`、不标 `citable` |

档位由实际次数判定并写入 manifest；缩减档的报告在抬头与局限章注明"缩减次数执行，产物仅供内部调试"。

### 5.4 manifest 记录什么

`manifest.json` 扫描该 run 下全部产物，逐条记录：相对路径、所属子目录、字节数、sha256、
该文件自己声明的 `run_id` 与 schema；另外记录 bootstrap 次数、档位、是否 `citable`、
lineage（若有重生成，写明源 run）。用途是**禁止跨 run 串源**：任何报告引用的数字都能
追到具体文件与指纹。

### 5.5 归档与历史产物

历史 run 一律不删、不改；旧版流水线产物冻结在 `output/archive/`，只读。
解释报告重生成时写入新 run 目录并在 lineage 中标注源 run，源 run 一个文件都不动。

## 6. 已知问题（如实列出）

**① 稠密图上排序偏向出度大的响应量。**
在稳定边较多（约 59 条 / 15 变量）的模板中，总效应得分会放大"出边多"的中间变量，
实测某模板的前五名**全部是响应量**，且模型判定与知识条目一致地给出"不支持作为根因"。
这不是个别样本问题，是排序量本身的偏向，属**方法层面未解决**问题。

**② 没有独立真值。**
任何"与假设的一致度"都不是准确率；本工作不提供准确率、命中率类结论。

**③ 样本独立性不足。**
60 条轨迹在因果通道上只有 9 个不同排序（每类 3 个），跨模板比较与置信区间都缺少统计基础。

**④ 部分知识条目为人工补充、待专家确认。**
K2 的 5 条关系是教科书级常识；本次补充的 5 条响应量条目为人工按机理添加，标 `pending_expert`，
尚未经外部专家评审。

**⑤ 只覆盖 3 类。**
LOCA / SGATR / FLB 共 9 个模板；LOCAC 仅 5 条，其余 8 类无数据。任何"12 类全适配"的表述
都只是工程配置就绪，不是方法结论。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| 模板 | "事故类型 × 严重度组"，如 LOCA_low，共 9 个 |
| 稳定边 | bootstrap 中同向出现比例达阈值的边 |
| 总效应 | T=(I−B)⁻¹ 中，候选变量到效应变量集合的总因果效应绝对值之和 |
| 传导链 | 从候选变量出发、≤4 条边、指向效应变量的路径 |
| 证据包 | 交给模型的全部可用信息：候选、入出边与系数、变量字典、知识条目、预计算冲突 |
| 四态判定 | 支持 / 部分支持 / 不支持 / 无法判断 |
| pending_expert | 人工补充、尚未经外部专家确认的知识条目状态 |
| 结构健康度 | 节点数、稳定边数、边密度、条件数、截断条数等描述性量 |
| 缩减档 | bootstrap 5 次的测试档，产物不得引用 |
