### `NPPAD-CausalTrace-v2.3（对外版）-2026-11-11.md`

- **定位**：同一套方法的**对外呈现版**（导师/评审阅读），清掉内部修订记录与实验过程，只讲"是什么、怎么跑、能主张什么"；不引用任何验收数字作结论。
- **与内部工作版的关系**：方法与阈值的唯一口径仍是上面的内部工作版；两者冲突以内部工作版为准。**后续方案修改一律写回内部工作版**，除非用户明确说明要改对外版。
- **覆盖**：任务边界、数据现状（3/12 类可用）、方法主线、评测口径（只保留结构健康度与解释忠实性；稳定性推断量已取消）、运行复现、已知问题（含稠密图出度偏置）。

### `../issues/`（问题取证，不在方案目录内）

- **放什么**：指标可靠性审查、方向体检、量级核查等"记录问题"的文档；**不放**方案、对外版、对比稿、入口页。
- **索引**：`issues/README.md` 说明收录标准与命名规则；结论状态仍以 `Code/error_tracking.md` 为准。
- **动因**：问题类产物不应混在交付目录里（用户要求 2026-11-11）。

## 7. 新增/升级版本时的操作约定

1. **新增**：只新建文件，不改名、不移动任何既有文件。
2. **旧版处置**：在旧文件**首行**加一行状态标记（例：`> 状态：已被 v2.3-final 取代，方法定义以现行版为准（归档，不删）`），正文其余部分不动。
3. **索引**：同步更新本文件第 3–6 节（现行版、并行线、归档、谱系表）。
4. **口径变更**：凡影响阈值/常量/统计单位/窗口的变更，必须同时更新现行版 §0.2 冲突裁决表，并在 `Code/error_tracking.md` 登记。
5. **状态信息**：不写进方案正文；验收/问题状态只写台账。
