## 3. V2.3 对各历史版本的复用关系（核心）

### 3.1 复用自 V1（实验复现方案）

V1 是整个项目的方法论起点，V2.3 在算法核心层沿用其双引擎框架。

| 复用项 | V1 原始定义 | V2.3 复用方式 | 复用位置 |
|--------|-----------|--------------|---------|
| **LiNGAM 因果发现** | ICA-based LiNGAM 构建 DAG | 直接复用，作为因果发现主引擎 | run_signature.py / 算法层 |
| **GAM-ANM 因果发现** | GAM-ANM 替代完整 DiffAN | 直接复用，作为第二引擎 | run_signature.py / 算法层 |
| **共识边融合** | 两引擎结果取共识边 | 直接复用，consensus 边判定 | run_signature.py |
| **RRF 融合** | 残差重加权融合 | 直接复用，稳定边融合 | run_signature.py |
| **物理约束层思路** | 变量关系需有物理依据 | 扩展为 ALLOWED_RELATIONS + 禁止边规则 | knowledge.py |

**复用比例**：算法核心层 ~80% 直接沿用 V1 方法，V2.3 未修改双引擎与融合逻辑。

---

### 3.2 复用自 V2（跨事故因果签名 RCA）

V2 提出了跨事故类型的因果签名框架，V2.3 继承其签名结构思路但调整了应用场景。

| 复用项 | V2 原始定义 | V2.3 复用方式 | 复用位置 |
|--------|-----------|--------------|---------|
| **因果签名结构** | 类级签名 c_k（每类事故一个特征向量） | 扩展为类×严重度组签名 c_{k,g}（V2.1 已升级，V2.3 沿用） | signature JSON schema |
| **两级 RCA 架构思路** | V2 事故级 + V1 变量级 | V2.3 聚焦事故内溯源，保留"签名→溯源"两级结构 | 端到端流程 |
| **溯因诊断框架** | SD, COMPONENTS, F={f_k}, OBS, Reiter/Poole 口径 | 继承诊断形式化定义（V2.1 沿用，V2.3 隐式继承） | 根因溯源逻辑 |

**复用说明**：V2.3 不直接复用 V2 代码（V2 已被 V2.1 取代），但继承其签名框架设计思路。V2.1 是 V2 的直接取代版本，V2.3 通过复用 V2.1 间接继承 V2 的设计。

---

### 3.3 复用自 V2.1（神经符号正演-反演 RCA）

V2.1 是 V2.3 的**主要复用来源**，算法层、知识层、解释层均直接复用。

#### 3.3.1 算法层复用

| 复用项 | V2.1 实现 | V2.3 复用方式 | 代码模块 |
|--------|----------|--------------|---------|
| **类×严重度组签名** | 9 模板 c_{k,g}（3类×3严重度） | 扩展为 36 模板（12类×3严重度），签名结构不变 | run_signature.py |
| **轨迹级 Bootstrap** | 100/50 次重采样，四指标(f_e/s_e/方向/符号) | 直接复用，不修改 | run_signature.py |
| **Algorithm 1** | Bootstrap 边稳定性筛选（f_e≥0.5, s_e≥0.6） | 直接复用 | run_signature.py |
| **Algorithm 2** | 总因果效应 T=(I-B)⁻¹ | 直接复用 | signature JSON |
| **Algorithm 3** | 反事实验证（ΔB_pred vs ΔB_obs, gCF门控） | 直接复用，补充完整输出结构 | cf_validation.py |
| **共识边判定** | f_e≥0.5 且 s_e≥0.6 → consensus | 直接复用 | run_signature.py |
| **RRF 传播链** | marker 根 RRF 传播链 + 忠实性校验 | 复用传播链逻辑，marker 弱化（V2.2 已改） | chains.py |

#### 3.3.2 知识层复用

| 复用项 | V2.1 实现 | V2.3 复用方式 | 代码模块 |
|--------|----------|--------------|---------|
| **ENTITY_TABLE** | 变量实体表（含义/子系统/单位） | 扩展为 96 变量，结构不变 | knowledge.py |
| **ALLOWED_RELATIONS** | 允许的变量关系（按子系统） | 扩展为 12 类事故各自的允许关系 | knowledge.py |
| **_forbidden_rules** | 禁止边规则（R1/R2/R3） | 直接复用 + 外部 YAML 扩展 | knowledge.py, external_knowledge/forbidden_edges.yaml |
| **COMPETITIVE_PAIRS** | 竞争边（双向反馈环） | 直接复用 | knowledge.py |
| **过程本体（公差阈值）** | μ±3σ 阈值，恢复段基线 | 升级为每类事故 sev-1 独立基准 + 稳健σ(MAD×1.4826+σ_floor) | anomaly.py, tolerance_{k}.json |

#### 3.3.3 解释层复用

| 复用项 | V2.1 实现 | V2.3 复用方式 | 代码模块 |
|--------|----------|--------------|---------|
| **LLM 解释** | Phase 5.5 LLM 生成 RCA 报告 | 直接复用，扩展为 K3 机制模板 + LLM 双通道 | explanation.py |
| **忠实性校验** | 正则匹配变量名+数值 | 直接复用 | explanation.py |
| **模板解释** | 硬编码模板 | 扩展为 fault_templates.yaml 外部配置 | explanation.py |

#### 3.3.4 V2.1 实验结论复用

| 复用项 | V2.1 结论 | V2.3 应用 |
|--------|----------|----------|
| **共享基线 Z 病态** | sev-1 稳态段 σ≈0 导致 z 爆炸 | §4.4.1 数据审计必做项，稳健σ处理 |
| **严重度变点问题** | 固定分组导致合成伪影 | §4.4.2 变点检测，数据驱动分组边界 |
| **marker 行为差异** | 三类 marker 对 severity 行为不同 | §4.4.2 分组边界参考 |
| **硬编码变量集** | 3 类各 20 变量 | 作为变量选取失败时的回退方案（§8.4） |

**复用比例**：V2.3 ~60% 的代码与逻辑直接复用 V2.1，主要增量在变量选取机制（§3）、12类适配（§4）、知识融合工程化（§5）。

### 3.4 复用自 V2.2（变量溯源与因果图可视化）

V2.2 是 V2.1 的增量模块，V2.3 在溯源与可视化层直接复用。

| 复用项 | V2.2 实现 | V2.3 复用方式 | 代码模块 |

| **consensus 边过滤** | 只显示 consensus 边 | 直接复用 | graph_visualization.py |

**复用比例**：溯源与可视化层 ~90% 直接复用 V2.2，V2.3 增量在严重度分组决策（§4.6）与跨严重度汇总。
